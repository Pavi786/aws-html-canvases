✅ 2xx — Success Responses Request was received, understood & accepted
CodeNameDeep ExplanationWho Cares
200 OK The gold standard. Request succeeded. Response body contains the requested data. For GET it returns resource; for POST it returns result. DevOps monitors 200-rate as a health signal — drop in 200s = something is broken.
GET, POST, PUT, PATCH 		All sides
201 Created Resource was successfully created. Server should return a Location header pointing to the new resource. Always expected after a successful POST that creates data. If your API returns 200 on creation, that's a bad practice.
REST APIsPOST 		Backend Frontend
202 Accepted Request queued for async processing. Server accepted it but hasn't processed yet. Common in background job systems (Celery, Sidekiq, queues). Frontend must poll or use webhooks to know the final result.
Async JobsQueuesWebhooks 		Backend DevOps
204 No Content Success but nothing to return. Common for DELETE and PUT. Response body MUST be empty. Frontend devs often get confused when their fetch() resolves but response.json() throws — because body is empty by design.
DELETEPUTOPTIONS (CORS preflight) 		Frontend Backend
206 Partial Content Range request fulfilled. Used when client sends a Range header. Essential for video streaming (YouTube, Netflix), large file downloads with resume support. Server returns Content-Range header specifying what chunk was returned.
Video StreamingFile DownloadsCDN 		DevOps Backend
🔁 3xx — Redirection Responses Further action needed to complete the request
CodeNameDeep ExplanationWho Cares
301 Moved Permanently SEO-critical redirect. Browser AND search engines update their records. Method may change to GET. Use for permanent domain migrations (http→https, old-domain→new-domain). Cached aggressively — wrong 301 can haunt you for months.
SEONginxDomain Migration 		DevOps Frontend
302 Found Temporary redirect. Method may change to GET (historically inconsistent across browsers). Don't use for permanent moves — search engines won't transfer link equity. Common for post-login redirects and temporary maintenance pages.
Auth FlowsTemporary 		Backend Frontend
304 Not Modified Cache hit — no body sent. Client sends If-Modified-Since or ETag, server says "your cache is still valid". Zero bandwidth used. Critical for CDN performance. DevOps tunes cache headers to maximize 304 ratio.
CacheCDNETag 		DevOps Frontend
307 Temporary Redirect Redirect preserving HTTP method. Unlike 302, browser MUST repeat the same method (POST stays POST). Use when you need to redirect a POST request temporarily without downgrading it to GET.
POST RedirectAPI 		Backend
308 Permanent Redirect Permanent 307 — preserves method forever. Best practice for permanent redirects when you want POST to stay POST. The modern replacement for 301 in API contexts. SEO-friendly like 301.
REST APIsSEO 		Backend DevOps
❌ 4xx — Client Errors The request itself is the problem
CodeNameDeep ExplanationWho Cares
400 Bad Request Server couldn't parse the request. Malformed JSON, invalid query params, missing required fields, wrong content-type. Backend should return a descriptive body saying exactly what's wrong. Frontend must validate before sending.
ValidationJSON ParsingQuery Params 		Client Frontend
401 Unauthorized Who are you? Prove it. No valid authentication provided. Missing or expired JWT, bad API key, no Authorization header. Confusing name — it really means "unauthenticated". Browser may show a login dialog. Your app should redirect to login.
JWTOAuthAPI Keys 		Backend Frontend
403 Forbidden I know who you are, but NO. Authenticated but not authorized. Role/permission mismatch (user trying admin endpoint), IP blocked, resource access denied by policy. Different from 401 — user IS logged in, just lacks the permission.
RBACIAMPermissions 		Backend DevOps
404 Not FoundHOT Resource doesn't exist. Wrong URL, deleted resource, typo in path, route not registered. Can also be returned intentionally to hide existence of private resources (instead of 403). DevOps: check your ingress path rules and service discovery.
RoutingK8s IngressSPA Routing 		All sides
405 Method Not Allowed Wrong HTTP verb. Route exists but not for that method (POST to a GET-only endpoint). Server MUST return an Allow header listing valid methods. Common mistake: sending DELETE to a route that only handles GET/POST.
REST DesignCORS 		Client Backend
408 Request Timeout Client was too slow sending the request. Server closed connection waiting for client to finish sending headers/body. Different from 504 (which is server-side timeout). Often seen with slow mobile connections or large uploads.
TimeoutsUpload 		DevOps Client
409 Conflict State conflict in server data. Creating a resource that already exists (duplicate email), version conflict in optimistic locking, editing a stale record. Client must resolve the conflict and retry. Common in distributed systems.
Optimistic LockingUnique Constraints 		Backend Frontend
410 Gone Permanently deleted — update your links. Like 404 but permanent. Search engines remove it from index. Use for content that was intentionally deleted and won't come back. Unlike 404, this tells crawlers "stop trying".
SEODeleted Content 		DevOps Frontend
413 Payload Too Large Request body exceeds server limit. Nginx default is 1MB. If you're uploading files and hitting 413, increase client_max_body_size in Nginx or body-parser limit in Node. Check both app server AND reverse proxy limits.
File UploadNginx Config 		DevOps Backend
415 Unsupported Media Type Wrong Content-Type header. Server can't process the format sent. Most common: forgetting Content-Type: application/json when sending JSON, or sending multipart/form-data to an endpoint expecting JSON.
Content-TypeHeaders 		Client Frontend
418 I'm a Teapot ☕ April Fools' RFC 2324. "Any attempt to brew coffee with a teapot should result in 418." Meant as a joke in 1998 but was kept in HTTP spec. Some APIs actually use it for "I refuse to process this" easter eggs. Node.js has it built in!
Easter EggRFC 2324 		Fun
422 Unprocessable EntityHOT Validation failed — right format, wrong values. Request was well-formed (parseable) but semantically invalid (email missing @, age is negative, required field empty). This is the right code for form validation errors. JSON body should list exact field errors.
Form ValidationSchema ValidationZod / Pydantic 		Frontend Backend
429 Too Many RequestsHOT Rate limit exceeded. Client hit the request quota. Response should include Retry-After header. Common with public APIs (GitHub, OpenAI, Stripe). DevOps implements rate limiting at API Gateway, Nginx, or application layer. Frontend must implement retry with exponential backoff.
Rate LimitingAPI GatewayRetry 		DevOps Backend Client
451 Unavailable For Legal Reasons Censored by law. Content legally blocked in user's region. Named after Fahrenheit 451. Used by governments, GDPR takedowns, DMCA. Should include a Link header to the blocking authority. Netflix geo-restrictions sometimes manifest this way.
GDPRDMCAGeo-blocking 		DevOps Backend
💥 5xx — Server Errors Server failed — not the client's fault
CodeNameDeep ExplanationWho Cares
500 Internal Server ErrorHOT Unhandled exception in your code. Catch-all for server crashes. Usually means an unhandled exception, null pointer, uncaught promise rejection, or DB connection failure. Check server logs immediately. Never expose stack traces to client in production. Instrument with Sentry/Datadog.
ExceptionsLogsSentryDB Errors 		Backend DevOps
502 Bad GatewayHOT Proxy got a garbage response from upstream. Nginx/Load Balancer asked your app server, got an invalid response (or none). Most common causes: app crashed/restarting, returning invalid HTTP, mismatched protocol. Check: is your pod running? Is the port correct? Did the app panic on startup?
NginxLoad BalancerK8sProxy 		DevOps
503 Service UnavailableHOT Server alive but refusing connections. Server is overloaded, in maintenance, or no healthy pods available. In K8s: pod not ready (readiness probe failing), deployment rolling update in progress. Add a Retry-After header. DevOps: check HPA, resource limits, OOMKilled pods.
OverloadK8s ReadinessMaintenanceHPA 		DevOps
504 Gateway TimeoutHOT Upstream took too long to respond. Nginx waited for your app and gave up. Common causes: slow database query, heavy computation, external API call hanging, deadlock. Fix: optimize the slow operation, increase proxy timeout temporarily, add async processing. Check APM traces for the bottleneck.
TimeoutsSlow DBAPMNginx proxy_read_timeout 		DevOps Backend
507 Insufficient Storage Server ran out of disk space. Server cannot complete the request because the storage is full. Critical alert in DevOps monitoring. Check with df -h. Common in log accumulation, database growth, Docker image buildup. Set up disk alerts at 80%.
Disk FullMonitoringAlerts 		DevOps
508 Loop Detected Infinite redirect or WebDAV loop. Server detected an infinite loop in the request chain. Common with misconfigured reverse proxies, circular redirects in Nginx/Apache, or WebDAV processing loops. Check your redirect rules for circular references.
Nginx ConfigRedirect Loops 		DevOps
511 Network Authentication Required Captive portal — you need to login to the network. Used by hotel/airport WiFi interceptors. The client needs to authenticate at network level (not application level) before the request can proceed. Not usually seen in production services.
Captive PortalNetwork 		DevOps Client

⚡ Nginx / Load Balancer Errors
502
Upstream app returned invalid HTTP or crashed
Fix: Check if app process is alive. Verify port. Check app logs for panic/crash.
504
Nginx waited, upstream didn't respond in time
Fix: Check proxy_read_timeout. Profile slow DB queries. Add APM tracing.
499
Client closed connection before server responded (Nginx-specific)
Fix: App is too slow. Client gave up. Optimize response time or show loading states.
413
Upload too large, blocked by Nginx before hitting app
Fix: Set client_max_body_size in nginx.conf. Match app's body-parser limit.
☸️ Kubernetes Errors
503
Pod not ready — readiness probe failing or no pods
Fix: kubectl describe pod. Check readinessProbe. Check HPA / resource limits.
502
Service can't reach pod — wrong port, pod crashed
Fix: kubectl get endpoints. Verify targetPort matches containerPort.
404
Ingress path not matching — wrong path rules
Fix: kubectl describe ingress. Check path prefix vs exact match. Check rewrite-target.
504
Pod responding too slowly — timeout at ingress level
Fix: nginx.ingress.kubernetes.io/proxy-read-timeout annotation.
🔐 Auth & API Errors
401
Missing or expired token — not authenticated
Fix: Check JWT expiry. Refresh token flow. Verify Authorization header is being sent.
403
Authenticated but wrong role/scope/permission
Fix: Check RBAC config. Verify token scopes. Check IAM policies (AWS/GCP).
422
Validation failed — wrong field values
Fix: Read error body carefully. Map field errors to UI. Fix schema validation logic.
429
Rate limit hit — too many requests from client
Fix: Implement exponential backoff. Check Retry-After header. Review rate limit config.
🔥 500 Debug Checklist
Step 1
Check application logs immediately
kubectl logs <pod> --previous | journalctl -u app
Step 2
Check for unhandled exceptions / panics in code
Sentry, Datadog, CloudWatch Logs
Step 3
Check DB connectivity and query errors
Connection pool exhausted? Slow query? Migration pending?
Step 4
Check memory / CPU — OOMKilled?
kubectl describe pod | grep -i oom | kubectl top pods
