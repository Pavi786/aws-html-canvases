Compute Services
Compute is the brain of your cloud architecture — where code runs, apps are hosted, and logic executes. The single most impactful architectural decision you'll make is choosing the right compute service.
🖥️ Virtual Machines (VMs) IaaS
Layman Way

Like renting a fully equipped computer inside Microsoft's data center. You pick the size (CPU/RAM), choose the OS (Windows or Linux), and you have full control — install any software, configure any settings, run any workload. It's your computer, just hosted in the cloud.

Pro Architecture — IaaS Responsibility Split
  • You manage: OS, runtime, middleware, application, data
  • Azure manages: hardware, physical host, networking fabric, storage backend
  • Hypervisor: Azure uses custom Hyper-V hypervisor on bare metal hosts
  • VM Generation: Gen2 VMs support UEFI boot, larger OS disk, more RAM. Always prefer Gen2 for new workloads
  • Accelerated Networking: SR-IOV bypasses hypervisor for NIC — reduces latency by 70%, use always in prod

Availability Deep Dive:

  • Availability Set: Protects against hardware failures in SAME datacenter. Fault domains (different racks) + Update domains (rolling patches). SLA 99.95%
  • Availability Zone: Protects against ENTIRE datacenter failure. Physically separate buildings with own power/cooling/networking in same region. SLA 99.99%
  • VMSS (Scale Set): Auto-scale identical VMs based on metrics. Supports AZs + Spot VMs + Load Balancer integration. Orchestration modes: Flexible (mix VM types) vs Uniform (identical)
  • Rule: For max HA → Availability Zones. For same-AZ redundancy → Availability Sets. For auto-scaling → VMSS. For absolute max → VMSS across AZs
  • SLA Stacking: 2 VMs in different AZs = 99.99%. 1 VM with Premium SSD = 99.9%. 1 VM with Standard SSD = 99.5%. Never run single VMs in prod
🌍 REAL-WORLD DEVOPS SCENARIO — Java Spring Boot with Variable Traffic
  • Problem: Java Spring Boot app must handle variable traffic (10x spikes), high availability, cost-efficient
  • Create a VM Scale Set (VMSS) with custom VM image (app pre-installed via Packer + CI/CD)
  • Set min=2, max=20 instances across 3 Availability Zones
  • Configure auto-scale: CPU > 70% → add 2 VMs; CPU < 30% → remove 1 VM (with 5-min cooldown)
  • Put Azure Application Gateway in front for load balancing + SSL termination + WAF
  • Use Spot VMs for 30% of the fleet to reduce cost (with eviction policy: delete)
  • Result: HA app, auto-scaling, ~40% cost reduction vs all on-demand, zero manual intervention

✅ VM DO's
  • Always deploy across multiple Availability Zones for prod
  • Use Managed Disks (Premium SSD) for OS and data disks
  • Enable Accelerated Networking (SR-IOV) on supported VMs
  • Use VM Extensions to automate agent installs (OMS, AMA, custom scripts)
  • Enable Azure Backup with appropriate retention policy
  • Tag every VM: Environment, Team, Project, CostCenter
  • Use Bastion instead of public IP for SSH/RDP access
  • Enable boot diagnostics and guest OS diagnostics
  • Apply Just-in-Time (JIT) VM Access for admin ports
  • Use Azure Monitor Agent (AMA) — replaces old MMA/OMS agents
❌ VM DON'Ts
  • NEVER expose port 22 (SSH) or 3389 (RDP) to 0.0.0.0/0
  • NEVER run single VM in prod without zone redundancy
  • AVOID storing app data on OS disk — use data disks or Blob
  • AVOID paying On-Demand for VMs running 24/7 — use Reserved
  • NEVER leave unused VMs running — Stop = Deallocate, not just Stop
  • AVOID unmanaged disks (deprecated, management overhead)
  • NEVER ignore VM patch status — enable automatic VM guest patching
  • AVOID oversizing — review Azure Advisor recommendations weekly

🐳 AKS — Azure Kubernetes Service Container Orchestration
Layman Way

Like a sophisticated shipping port manager. Ships (containers) arrive, the port manager decides which dock (node/server) each ship goes to, makes sure the right number of ships are always at port, replaces broken ships automatically, and manages all traffic routing. AKS is this port manager — Azure manages the control tower (control plane) for FREE, you only pay for dock workers (nodes/VMs).

AKS Networking Modes — Critical Choice
  • kubenet (basic): Pods get private IPs behind NAT. Simpler, no VNet IP exhaustion, but limited: no network policies by default, no private peering from outside VNet
  • Azure CNI: Each pod gets a real VNet IP. Better for prod: full NSG support, VNet peering works natively, Private Endpoints reachable. Requires IP planning — runs out fast
  • Azure CNI Overlay: Pods use private overlay IPs but Azure CNI features. Best of both — choose this for new clusters
  • Network Policy: Calico (cross-platform) or Azure NPM. Always enable in prod

Storage Services
Azure storage covers every data type — files, blobs, disks, tables, queues, and massive data lakes. The right storage service directly impacts performance, cost, and architectural simplicity.
🗄️ Azure Blob Storage Object Storage
Layman Way

A massive, infinitely scalable hard drive in the cloud. 'Blob' = Binary Large Object. Store anything: images, videos, backups, log files, ML models, app artifacts, static website files. Fractions of a penny per GB, scales to exabytes automatically, no server to manage.

Blob Types — When to Use Each
  • Block Blobs: Files, data, documents, images, videos — 99% of use cases. Up to 4.77 TB. Optimized for sequential reads/writes
  • Page Blobs: VM disks (VHD format). Random read/write at page (512-byte) granularity. Up to 8 TB
  • Append Blobs: Logs — append-only operations. Cannot update previous blocks. Perfect for logging, audit trails

Lifecycle Management — Auto-Tiering (Set It & Forget It):
Create rules to automatically move blobs between tiers based on age:

Networking Services
Networking is the invisible glue connecting every Azure service. A poorly designed network means security breaches, high latency, and unreachable services. A well-designed network means secure, fast, highly available connections between everything.
🏙️ Azure Virtual Network (VNet) Core Network Foundation
Layman Way

Like building your own private city inside Azure. You decide the streets (subnets), the neighborhoods (IP address ranges), the gated communities (NSGs), the highways to other cities (VNet peering), and the tunnels to your home office (VPN Gateway / ExpressRoute). Nobody enters your city unless you specifically open the gate.

IP Planning — Critical to Get Right
  • VNet CIDR: Use RFC 1918 — /8, /16, /24. Pick large enough range (e.g. 10.0.0.0/16 = 65,534 IPs)
  • No overlapping: If VNets peer, their CIDRs cannot overlap. Plan before deploying
  • Reserved per subnet: Azure reserves 5 IPs per subnet (first 4 + last)
  • AKS Azure CNI: Each pod consumes a VNet IP — plan for max_pods × max_nodes additional IPs
  • Service Endpoint vs Private Endpoint: Service Endpoint = optimized route, still uses public IP of PaaS. Private Endpoint = private IP in your VNet, traffic fully private

💰 COSMOS DB COST MODEL — UNDERSTAND BEFORE YOU USE
  • Provisioned Throughput: Pay for RU/s reserved 24/7. Min 400 RU/s per container = ~$23/month. Predictable but potentially wasteful
  • Autoscale: Set max RU/s, Cosmos scales between 10%–100% automatically. ~10-25% more per RU than provisioned but great for variable traffic
  • Serverless: Pay per actual RU consumed. No minimum. Perfect for dev/test or very bursty workloads (<5M RU/month)
  • Storage: $0.25/GB/month regardless of tier

⚠️ CRITICAL COST TRAP: Each container needs minimum RU/s. 100 containers × 400 RU/s = $2,300/month minimum! Use shared throughput at database level — up to 25 containers share the pool.

💡 Best Practice: Use Serverless for dev/test. Autoscale with shared database throughput for production. Only use per-container provisioned RU for high-traffic isolated containers.

Partition Key Selection — Make or Break Decision:

  • Good choices (high cardinality): userId, orderId, deviceId, productId — millions of unique values
  • Bad choices (low cardinality): country (200 values), status (3 values), date (limited) — creates hot partitions
  • Hot partition symptoms: 429 "TooManyRequests" errors on specific partition, uneven RU consumption
  • Synthetic partition key: Combine multiple fields when single field isn't selective enough (e.g., userId + month)
  • Hierarchical partition keys: Cosmos DB now supports up to 3-level partition key for sub-partitioning (e.g., tenantId/userId/sessionId)

Top 25 Facts Every Azure Pro Must Know
Memorize these. They come up in every interview, every exam, every production incident post-mortem.
01
VMs in Availability Zones = SLA 99.99%
Always use zones for production VMs. Single VM with Premium SSD = 99.9% only.
02
Managed Identity = zero passwords for service-to-service auth
Security best practice — no secrets in code, config, or environment variables. DefaultAzureCredential works everywhere.
03
Azure Policy 'Deny' blocks non-compliant resource creation
Enforce governance before problems occur — reactive auditing is too late. Shift governance left.
04
Cosmos DB partition key MUST be high-cardinality
Wrong partition key = hot partition = 429 throttling errors = degraded performance for ALL users on that partition.
05
App Service Deployment Slots = zero-downtime blue/green
Swap staging→production in seconds. Roll back by swapping back. Slot settings (like connection strings) can be sticky.
06
Functions Consumption plan = cold start (1–3 sec)
Use Premium plan (pre-warmed) for latency-sensitive APIs. Consumption fine for async/background tasks.
07
Key Vault purge protection: once on, can't turn off
Enable for compliance — prevents permanent deletion during retention period even by vault owners.
08
Private Endpoint = PaaS access via VNet private IP
Traffic never traverses public internet. Essential for compliance-sensitive workloads. Disable public access too.
09
NSG is stateful — return traffic auto-allowed
Only need to define inbound rules for incoming traffic. NSG automatically allows return packets of established connections.
10
AKS control plane = FREE — you pay only for nodes
Azure manages API server, scheduler, etcd at no charge. EKS was free since 2024 too but historically charged $0.10/hr.
11
Blob Archive tier retrieval = hours (must rehydrate first)
Rehydration to Hot: Standard priority ~15hr, High priority ~1hr. Plan retrieval time. Not for data needed quickly.
12
Log Analytics uses KQL — Kusto Query Language
Learn KQL — used everywhere: Azure Monitor, Sentinel, Defender, Application Insights, ADX. Not SQL but similar.
13
Conditional Access requires Entra ID P1 or P2 license
Check licensing before recommending CA policies. P2 adds Identity Protection, PIM, Access Reviews.
14
ExpressRoute = private connection, NOT over internet
Traffic flows via partner provider's private circuit. Up to 100Gbps. Required for regulated industries (banking, healthcare).
15
Soft Delete = safety net for accidental deletion
Enable for VMs (Recovery Services Vault), Blob (30 days), Key Vault (90 days). No performance impact. No downside.
16
Azure Hybrid Benefit saves up to 55% on Windows VM licensing
Apply always if you have existing Windows Server or SQL Server licenses. Also applies to SQL MI, AKS node pools.
17
VNet Peering is NOT transitive
Spoke-A → Hub → Spoke-B requires Azure Firewall or Route Server in Hub. You must add UDR to force traffic through Hub.
18
Durable Functions = stateful serverless (orchestrator + activities)
For complex multi-step workflows, fan-out/fan-in, human approval, long-running processes. Uses Azure Storage for state.
19
Azure Front Door = global HTTP LB + WAF + CDN in one
One service for global web app delivery. Anycast routing, SSL offloading, WAF policies, caching, origin groups.
20
Deallocate VMs when not needed — Stop is NOT enough
'Stopped' VM still charges for compute. 'Deallocated' releases compute — only storage charges remain.
21
Azure SQL Hyperscale = up to 100TB, fast backups
Distributed storage architecture. Backups in seconds (not hours). Horizontal read scale via secondary replicas.
22
PIM = Just-in-time privileged access with approval
Limit standing admin access to zero. Request → Approve → Time-limited (e.g. 8hr) → Auto-expire. Audit trail of all activations.
23
Defender for Cloud Secure Score = your security posture %
Target 80%+. Track weekly. Each recommendation has a score impact — prioritize high-impact items first.
24
Azure Monitor Metrics = 93 days, Logs = 30–730 days
Plan long-term archival to Storage Account or Event Hub. Log Analytics ingestion costs ~$2.30/GB — control what you ingest.
25
WORM (Immutable Blob) = cannot delete or modify during compliance period
Required for SEC Rule 17a-4, FINRA, HIPAA, MiFID II retention. Time-based retention or legal hold policies.
