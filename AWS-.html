Domain 1 — Design Secure Architectures

The BIGGEST domain (30%) · IAM · VPC · KMS · WAF · Shield · Secrets Manager

👤 IAM — Identity & Access Management
🏠 Layman Way IAM is your office SECURITY GUARD + KEY CARD SYSTEM combined. The janitor gets keys to the break room, NOT the server room. IAM enforces this — every person and service gets ONLY what they need. This golden rule is called Principle of Least Privilege — the #1 exam concept in security.
🏗️ IAM Components
ComponentWhat It IsReal Example
👤 UserA real human or app identitydeveloper@company.com logs into console
👥 GroupBucket of users with same policiesDevelopers group → EC2 read access
🎭 RoleTemporary identity for AWS servicesEC2 assumes role → automatically gets S3 access
📜 PolicyJSON document — Allow or Deny specific actionsAllow: s3:GetObject on arn:aws:s3:::my-bucket/*
🚧 Permission BoundaryMaximum permissions cap — can't exceed thisDev can create policies but CANNOT grant admin
🌐 SCP (Org Policy)Account-level guardrail across all users+rolesOrg: no one can disable CloudTrail, ever
🎯 EXAM TIP — Must Know!
  • Roles for Services: EC2, Lambda, ECS tasks → always use IAM Roles (auto-rotating temp creds)
  • Users + MFA: Humans logging into console → IAM User with MFA enabled
  • NEVER: Hardcode AWS_ACCESS_KEY_ID in code, .env files, GitHub repos, or S3 buckets
  • ALWAYS: Rotate access keys every 90 days, delete unused credentials immediately
  • Root Account: Enable MFA, never use for daily tasks, create NO access keys
💻 Mastery Commands
# ── CREATE IAM ROLE FOR EC2 ────────────────────────────────── aws iam create-role --role-name EC2-S3-ReadRole \ --assume-role-policy-document file://trust-policy.json # Attach managed policy aws iam attach-role-policy --role-name EC2-S3-ReadRole \ --policy-arn arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess # Create instance profile & attach role aws iam create-instance-profile --instance-profile-name EC2Profile aws iam add-role-to-instance-profile \ --instance-profile-name EC2Profile --role-name EC2-S3-ReadRole # ── TERRAFORM IAM ROLE ────────────────────────────────────── resource "aws_iam_role" "ec2_role" { name = "EC2-S3-ReadRole" assume_role_policy = jsonencode({ Version = "2012-10-17" Statement = [{ Action = "sts:AssumeRole", Effect = "Allow", Principal = { Service = "ec2.amazonaws.com" } }] }) }

✅ Do's

  • ✅ Enable MFA on root account — ALWAYS
  • ✅ Use IAM Roles for EC2/Lambda (never access keys)
  • ✅ Follow Least Privilege — start with nothing, add only what's needed
  • ✅ Use IAM Groups to manage users at scale
  • ✅ Enable CloudTrail — logs every single API call
  • ✅ Use Permission Boundaries in AWS Organizations

❌ Don'ts

  • ❌ NEVER use root account for daily tasks
  • ❌ NEVER hardcode credentials in application code
  • ❌ NEVER give AdministratorAccess to applications
  • ❌ NEVER share IAM user credentials between people
  • ❌ NEVER create access keys for root account
  • ❌ NEVER store secrets in S3, GitHub, or app logs
💰 Cost & Pricing IAM is 100% FREE. No cost for users, groups, roles, policies, or MFA. The ONLY cost is your time to set it up correctly. No excuse for poor IAM hygiene!
🌐 VPC — Virtual Private Cloud
🏠 Layman Way VPC = building your OWN CITY inside AWS. You design the streets (subnets), install city gates (internet gateways), create private neighborhoods (private subnets), set up guards (SGs & NACLs), and build private roads (VPC Peering & Transit Gateway). Nobody enters your city unless you explicitly allow them.

🏠 Private SubnetResidential areaNO internet route. Databases and app servers. Much safer.

💻 EC2 + Auto Scaling Groups
🏠 Layman Way EC2 = renting a computer from Amazon's data center. Auto Scaling Group (ASG) is the MAGIC — it watches your servers like a hawk: too busy? Add more automatically. Traffic drops? Remove them to save cost. Server dies? Replace it in minutes. You set the rules, ASG executes them 24/7.
💰 EC2 Pricing Models — Choose Wisely!
Pricing ModelMax SavingsCommitmentBest Use Case
🏷️ On-DemandBaseline (0%)None — pay by hour/secDev/test, unpredictable spiky workloads
📅 Reserved 1-YearUp to 40% off1 year commitmentSteady production servers (web app, API)
📅 Reserved 3-YearUp to 72% off3 year commitmentStable long-running DBs, critical infra
⚡ Compute Savings PlanUp to 66% off1-3 yr $/hr spendFlexible: covers EC2 + Lambda + Fargate
🎰 Spot InstancesUp to 90% offNone — interruptibleBatch jobs, ML training, fault-tolerant
🏠 Dedicated HostVariesOn-demand or reservedBYOL software licensing, strict compliance
🎯 EC2 Pricing Quick Rules
  • Predictable 24/7 workload × 3 years: → Reserved Instances (3yr All-Upfront) = MAXIMUM savings (72%)
  • Mixed EC2+Lambda+Fargate workloads: → Compute Savings Plans (most flexible)
  • Batch ML training that tolerates interruption: → Spot Instances (90% off)
  • Short-term dev environment: → On-Demand (no commitment)
  • Per-socket/per-core software license: → Dedicated Host
🔄 ASG — Auto Scaling Group Deep Dive
ASG ConceptDeep Explanation
Launch TemplateBlueprint: AMI, instance type, SG, key pair, user data, IAM profile. Version-controlled.
Min / Max / DesiredMin=floor (never go below), Max=ceiling (never exceed), Desired=current running target
Target Tracking PolicyKeep metric at target (e.g., avg CPU=60%). AWS auto-calculates scale in/out. EASIEST to use.

Predictive ScalingML analyzes historical patterns and PRE-SCALES before traffic arrives. Exam hot topic!
Health ChecksEC2 check (is instance running?) vs ELB check (is app healthy?). Always use ELB in prod.

🎯 Load Balancer Quick Picks
  • Path-based routing (/api → A, /web → B)? → ALB
  • Static IP for customer firewall whitelisting? → NLB (Elastic IP per AZ)
  • Ultra-low latency UDP gaming server? → NLB (Layer 4, sub-millisecond)
  • WebSockets or gRPC? → ALB (native support)
  • Inspect all packets with 3rd-party firewall? → Gateway Load Balancer
🆘 Disaster Recovery Strategies
DR StrategyRTO / RPOHow It Works & Cost
🗄️ Backup & RestoreRTO: Hours-Days / RPO: HoursCHEAPEST. Backup to S3 Glacier. Restore when disaster hits. Use AWS Backup.
🕯️ Pilot LightRTO: 10s of mins / RPO: MinutesCore DB always running in DR region. App servers OFF. Scale up on disaster.
🔥 Warm StandbyRTO: Minutes / RPO: SecondsScaled-down version ALWAYS running in DR region. Scale to full on disaster.
🚀 Multi-Site Active-ActiveRTO: Near Zero / RPO: Near ZeroMOST EXPENSIVE. Two full environments running simultaneously. Route 53 routes both.
🎯 RTO vs RPO — Critical Distinction
  • RTO = Recovery TIME Objective — how LONG to recover. 'Back online in 4 hours' = RTO 4hr
  • RPO = Recovery POINT Objective — how much DATA LOSS is acceptable. '1 hour of data loss OK' = RPO 1hr
  • Rule: Lower RTO/RPO = more infrastructure running = MORE EXPENSIVE. Balance business needs with budget.

λ AWS Lambda — Serverless Compute
🏠 Layman Way Lambda = a vending machine that only turns on when you press a button. Write your function code, upload it. Lambda handles ALL servers, scaling, OS patches, and infrastructure. Pay ONLY when your code runs — in milliseconds. 10,000 users hit your app at once? Lambda spins up 10,000 concurrent instances automatically in milliseconds.
Lambda ConceptDeep Explanation
🎯 TriggersAPI Gateway, S3, DynamoDB Streams, SQS, SNS, CloudWatch Events, ALB, Cognito, Step Functions...
🧠 Memory (128MB–10GB)CPU scales proportionally with memory. More memory = more CPU = faster = higher cost per ms.
⏱️ Timeout (max 15min)Default 3 sec. For >15 min jobs: use Step Functions orchestration or ECS Tasks.
🔄 ConcurrencyDefault 1000/region. Each request = 1 execution. Set Reserved Concurrency to prevent throttling.
❄️ Cold StartFirst invocation: container init takes 100-3000ms extra. Fix: Provisioned Concurrency (pre-warmed).
📦 LayersShared deps/libs packaged separately. Up to 5 layers/function. Share across functions.
🌐 VPC IntegrationLambda can run inside VPC to access private RDS/ElastiCache. Adds cold start time. Use RDS Proxy!
🌍 Lambda@EdgeRun Lambda at CloudFront edge locations (450+ globally) for auth, redirects, A/B testing.
💰 Lambda Pricing Requests: $0.20 per 1M requests (first 1M free forever) · Duration: $0.0000166667 per GB-second (first 400,000 GB-sec free/month)
Example: 1M requests × 200ms × 512MB = ~$1.67/month TOTAL · vs EC2 t3.micro 24/7: ~$8.50/month even when completely idle

🎯 CodeDeploy Deployment Strategies
  • In-Place (Rolling): Deploy to existing instances in batches. Brief downtime possible. Fastest rollback via redeploy.
  • Blue/Green: New instances (green) get new version. Traffic switches. Blue kept for instant rollback. Zero downtime.
  • Canary: 10% traffic to new version first → monitor → 100%. Safest for critical production apps.
  • Linear: Shift traffic in equal steps (e.g., 10% more every 10 minutes). Gradual and controlled.
  • All-at-Once: Fastest but causes downtime. Only for dev/test environments.
