03 — Interview Questions & Pro Answers
🔥 Top DevOps Interview Questions — Answer Like This #06
QUESTION THEY ASKWHAT A PRO ANSWERS (not what a junior says)
"What is Docker?" Don't define it. Say: "I use Docker to package apps with their dependencies. In practice I write multi-stage Dockerfiles to keep images under 50MB and scan them with Trivy in CI."
"How does K8s work?" Walk through: kubectl → API Server → etcd → Scheduler → Kubelet → Container Runtime. Then mention: "I've debugged pod scheduling issues with kubectl describe and events."
"What is GitOps?" "Git is the single source of truth. ArgoCD watches the repo and syncs cluster state to match it. If someone manually changes the cluster, ArgoCD reverts it. I've used this with App-of-Apps pattern."
"How do you handle secrets?" "We use Vault with dynamic secrets — apps get short-lived credentials that expire. I also use Sealed Secrets in K8s so encrypted secrets live in Git safely."
"What happens when prod is down at 3am?" Walk through: "Check Grafana alerts → kubectl logs/describe → check recent deployments in ArgoCD → roll back if needed → postmortem next day." Shows process, not panic.
"Difference between SLO and SLA?" "SLO = internal target (99.9%). SLA = external contract with penalty. Error budget = gap between SLO and 100%. We track this in Grafana to decide if we can deploy."
💥 Scenario Questions — Think Out Loud #07
Scenario questions test HOW you think, not what you know. Think out loud. Ask clarifying questions. Show process.
  • 🔥
    "Prod is slow, what do you do?"
    Say: "First check Grafana — CPU, memory, latency. Then check recent deploys in ArgoCD. kubectl top pods for resource usage. Check logs in Kibana. If a bad deploy, rollback. If infra, scale out. After fix, postmortem."
  • 🚀
    "Design CI/CD for a new microservice"
    Say: "GitHub Actions: build → test → Docker build → Trivy scan → push to ECR. ArgoCD picks up new image tag via image updater. Deploy to staging first, run smoke tests, then prod with canary via Argo Rollouts."
  • 🔐
    "How do you secure a K8s cluster?"
    Say: "RBAC with least privilege, Network Policies between namespaces, Pod Security Standards (no root), Secrets via Vault/Sealed Secrets, Falco for runtime, Trivy in CI, no public endpoints without auth."
  • 📈
    "Traffic is 10x on Black Friday, how do you handle it?"
    Say: "HPA scales pods on CPU/RPS. Karpenter adds nodes automatically. Load tested with K6 beforehand. Pre-scaled the day before using scheduled scaling. Monitored real-time on Grafana dashboards during the event."

05 — Talk Like a Pro: Words That Signal Seniority
🗣️ Junior vs Senior Language — The Exact Words to Use #11
JUNIOR SAYS ❌SENIOR SAYS ✅
"I used Docker to run containers" "I containerized the app using multi-stage builds, reducing image size from 800MB to 120MB, and enforced distroless base images for security"
"I know Kubernetes" "I've managed a production K8s cluster — handled node pressure evictions, tuned resource requests/limits, and debugged CrashLoopBackOff issues"
"I set up monitoring" "I designed an observability stack with Prometheus for metrics, Loki for logs, Tempo for traces, and defined 12 custom alerts with PagerDuty routing"
"I know CI/CD" "I built a GitOps pipeline — GitHub Actions for CI, ArgoCD for CD with automatic rollback on health check failure, and Argo Rollouts for canary deployments"
"I used Terraform" "I wrote modular Terraform for multi-account AWS — VPC, EKS, RDS modules with remote state in S3 and DynamoDB locking, managed by Terragrunt across 4 environments"
"I fixed the issue" "I root-caused a memory leak in pod X by analyzing heap dumps — updated the HPA thresholds and added a resource limit that prevented OOMKilled events"
🧩 Mindset Shifts — Think Like Senior DevOps #12
The Core Mindset Difference
Junior: "I make the tool work."
Senior: "I use the tool to solve a business problem with measurable outcome."
  • 🎯
    Always connect tech to business impact
    "We moved to ArgoCD so devs ship 5x faster without waiting for ops. That means more features to customers." Business context = senior thinking.
  • ⚖️
    Give trade-offs, not just answers
    "Kafka is great for this but adds operational complexity — for this team size, SQS might be better because they don't need ordering." Trade-offs = architect thinking.
  • 📊
    Use data, not feelings
    "We reduced deploy time from 45min to 5min, that's 89% faster" hits harder than "deployments are much faster now." Numbers are facts. Facts are credible.
  • 🔮
    Think ahead — "What breaks at 10x?"
    Senior engineers design for scale they don't have yet. "This works fine now, but if traffic grows 10x, this DB will be the bottleneck — we should add read replicas."
  • 🤝
    Own failures — with a fix, not excuses
    "The deployment caused downtime — I wrote a postmortem and added automated smoke tests to prevent recurrence." Ownership + learning = senior signal.
