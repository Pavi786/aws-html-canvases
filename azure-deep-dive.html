Section 01
Compute Services
Compute
Virtual Machines (VM)
🖥️ Like renting a physical computer inside Microsoft's massive data center — you get CPU, RAM, and disk. You own everything on it.
Deep Explanation
Azure VM is Infrastructure-as-a-Service (IaaS). You choose your VM size (from basic B-series to GPU-powered NC-series), pick an OS image (Windows Server, Ubuntu, RHEL, etc.), and you're responsible for everything inside: OS updates, app installation, security patching, and networking config. Azure only guarantees the hardware underneath. VMs live inside a Resource Group and connect to a VNet for networking. They support managed disks (Premium SSD, Standard SSD, HDD) and can be part of a VM Scale Set (VMSS) for auto-scaling.
✅ Pros
Full OS-level control
Supports any language / stack
Lift & shift legacy apps easily
VMSS = auto scaling built-in
Reserved instances save 40–70%
❌ Cons
You manage OS patches yourself
Costs even when idle
Slower deployment vs containers
Overkill for small workloads
🏗️ Real-World Scenario
# Legacy Java ERP app migration
VM Size: Standard_D4s_v5 (4 CPU, 16GB RAM)
OS: Ubuntu 22.04 LTS
→ Install Tomcat + Java 17
→ Attach 256GB Premium SSD
→ VMSS: Scale 2→10 on CPU > 70%

  --resource-group MyRG \
  --name MyVM \
  --image Ubuntu2204 \

Serverless
Azure Functions
⚡ Run small pieces of code without managing ANY server. Pay only when your code actually runs — zero idle cost.
Deep Explanation
Azure Functions is a serverless compute service — you write a function (Python, Node.js, C#, Java, PowerShell), define a trigger (HTTP request, Blob upload, Queue message, Timer, Event Grid, Cosmos DB change, etc.), and Azure runs it. You never provision servers. Functions scale to zero, meaning zero cost when idle. There are 3 hosting plans: Consumption Plan (true serverless, auto-scale, pay-per-execution), Premium Plan (no cold start, VNet integration), and App Service Plan (always warm, predictable cost). Durable Functions enable stateful workflows like fan-out/fan-in patterns.
✅ Pros
Zero server management
Pay per millisecond of execution
Auto scales to millions of events
200+ built-in trigger/binding types
First 1M executions/month FREE
❌ Cons
Cold start latency (up to 3–10s)
Max 10-minute timeout (Consumption)
Stateless — hard to debug locally
Not for long-running processes

→ Function resizes image to 3 sizes
→ Sends metadata to Cosmos DB
→ Pushes notification via Event Grid
Cost: ~$0 for 500K images/month

Kubernetes
Azure Kubernetes Service (AKS)
🚢 Managed Kubernetes by Azure. You focus on deploying your containers — Azure manages the control plane, upgrades, and health.
Deep Explanation
AKS gives you a production-grade Kubernetes cluster where Azure fully manages the control plane (API server, etcd, scheduler) at no extra cost. You pay only for worker nodes (VMs). AKS integrates deeply with Azure services: Azure AD for RBAC, ACR for container registry, Azure Monitor for observability, Azure CNI or Kubenet for networking, and Azure Disk / Azure Files for persistent storage. Features include Cluster Autoscaler, Pod Autoscaler (HPA/VPA), Node Pools (mix of VM sizes), Spot Node Pools for 80% cost reduction, and GitOps with Flux built-in.
✅ Pros
Free control plane (save $150+/month)
Native Azure AD integration
Auto cluster & pod scaling
Multi-node pool support
GitOps + DevOps pipelines native
❌ Cons
Kubernetes learning curve is steep
Complex networking (CNI configs)
Upgrades need careful planning
Overkill for simple apps

PaaS
Azure App Service
🌐 Host web apps, REST APIs, or mobile backends without managing ANY server. Just push code — Azure handles the rest.

Containers
Azure Container Instances (ACI)
📦 Run a Docker container in Azure in under 30 seconds — no VMs, no Kubernetes, no clusters. Pure containers on demand.
Deep Explanation
ACI is the fastest way to run a container in the cloud. No cluster setup, no orchestrator needed. You define CPU and memory per container, provide a Docker image (from ACR or Docker Hub), and it starts in seconds. Great for batch jobs, CI/CD build agents, dev/test environments, or event-driven short tasks. Supports container groups (multiple containers sharing a network), persistent storage via Azure Files, environment variables, and secret management. ACI can even act as a virtual node in AKS for burst scaling.
✅ Pros
Starts in seconds — fastest launch
No cluster or VM to manage
Pay per second of CPU/memory use
Perfect for burst & batch workloads
❌ Cons
No auto-scaling built-in
Not designed for long-running apps
Limited networking compared to AKS
No load balancer integration

Section 02
Storage Services
Object Store
Azure Blob Storage
🪣 Infinite file storage in Azure. Store images, videos, PDFs, backups, logs — anything. Like Google Drive for your applications.
Deep Explanation
Blob = Binary Large Object. Azure Blob Storage has three types: Block Blobs (standard files up to 190.7 TB), Page Blobs (random-access, used for VM disks), and Append Blobs (append-only, great for logs). Storage accounts offer four access tiers: Hot (frequent access, higher storage cost), Cool (infrequent, 30-day minimum), Cold (rare access, 90-day min), and Archive (offline, retrieval hours, cheapest). Lifecycle management can auto-transition blobs between tiers. Supports soft delete, versioning, immutability policies, CDN integration, and static website hosting.
✅ Pros
Virtually unlimited capacity
Lifecycle rules for cost optimization
99.9999999% (11 9s) durability with GRS
Static website hosting built-in
SAS tokens for secure sharing
❌ Cons
No filesystem semantics natively
Archive retrieval takes hours
Egress data costs can add up
Not ideal for transactional data
Azure CLI
$ az storage account create --name mystorageacct \
  --resource-group MyRG --sku Standard_LRS
$ az storage container create --name mycontainer
$ az storage blob upload --file image.png --name img.png

Block Storage
Azure Disk Storage
💿 A managed virtual hard disk (VHD) attached to your VM. The OS runs on it, your databases store data on it.
Deep Explanation
Azure Managed Disks come in 4 types: Ultra Disk (up to 160,000 IOPS — for SAP HANA, SQL), Premium SSD v2 (flexible IOPS/throughput config), Premium SSD (production workloads), and Standard SSD / HDD (dev/test, cost-sensitive). Each VM gets an OS disk (C: or /) and can attach multiple data disks. Managed disks are automatically replicated within a zone/region. Supports disk snapshots, disk encryption (SSE with customer-managed keys), and shared disks for clustered applications.
✅ Pros
Ultra low latency (sub-ms for Ultra)
Managed = no storage account to manage
Snapshot-based backup
Encryption at rest by default
❌ Cons
Tied to a single VM (except shared disk)
Ultra Disk only in specific regions/zones
Cannot be accessed without attaching to VM

File + Analytics
Azure Files & Data Lake
📁 Azure Files = shared network drive for multiple VMs. Data Lake = massive analytics-grade storage for Big Data pipelines.
Deep Explanation
Azure Files provides fully managed SMB/NFS file shares — mount as a drive letter on Windows or mount point on Linux. Perfect for lifting shared storage from on-premises to cloud. Supports Azure File Sync for caching on-prem.

Azure Data Lake Storage Gen2 (ADLS Gen2) is Blob Storage with a hierarchical namespace enabled — enabling folder-level POSIX permissions, atomic operations, and 100x better Hadoop analytics performance. Used as the storage layer for Azure Synapse Analytics, Databricks, and HDInsight. Stores petabytes of raw, curated, and processed data in a medallion architecture (Bronze → Silver → Gold).
✅ Pros (Files)
SMB/NFS — works with existing apps
Mount from anywhere with Azure AD auth
File Sync for hybrid cloud scenarios
❌ Cons (Data Lake)
Complex permission model (ACLs)
Requires Spark/Synapse for querying
Not for OLTP — analytics only

Section 03
Networking
Foundation
Virtual Network (VNet)
🏗️ Your own private, isolated network inside Azure. Everything you build lives inside one. Think of it as your custom walled garden.
VNet is Azure's fundamental networking layer. You define a CIDR block (e.g., 10.0.0.0/16) and divide it into subnets (public, private, AKS, DB, etc.). Control traffic with NSGs (stateful firewall rules at subnet/NIC level), UDRs (custom routing), and Azure Firewall (managed NGFW). Connect VNets via VNet Peering (low latency, same or cross-region) or VPN Gateway/ExpressRoute for on-premises hybrid connectivity. Service Endpoints and Private Endpoints keep traffic off the public internet.
✅ Pros
Full isolation and control
Peer VNets globally without VPN
Private Endpoints = no public exposure
❌ Cons
CIDR planning errors are costly to fix
Peering costs on egress traffic
VNet peering is non-transitive

Traffic
Load Balancer & App Gateway
⚖️ Azure Load Balancer = Layer 4 traffic splitter. Application Gateway = Layer 7 smart router with WAF, SSL, and URL routing.
Azure Load Balancer (ALB) operates at Layer 4 (TCP/UDP). It distributes traffic across VMs or VMSS using health probes. Two types: Public LB (internet-facing) and Internal LB (private, between tiers). Supports Availability Zone-redundant frontend.

Application Gateway operates at Layer 7 (HTTP/HTTPS). It understands URLs — enabling path-based routing (/api → backend pool A, /images → backend pool B), multi-site hosting (host multiple domains), SSL termination, session affinity, and WAF v2 (OWASP 3.2 rules). Use with AKS Ingress Controller for Kubernetes workloads.
✅ Pros
ALB: ultra-low latency, zone-redundant
AppGW: URL-based routing flexibility
Built-in WAF on App Gateway v2
99.95% SLA on Standard tier
❌ Cons
App Gateway is expensive (v2)
ALB: no Layer 7 features
Config complexity for multi-site

DNS + CDN
Azure DNS & Front Door
📡 Azure DNS hosts your domain. Azure Front Door = global CDN + load balancer + WAF in one — serves users from the closest edge.
Azure DNS hosts your domain's DNS zones (A, CNAME, MX, TXT records) with 100% SLA uptime using anycast routing across 36 DNS PoPs globally. Supports Private DNS Zones for internal VNet name resolution.

Azure Front Door (AFD) is Microsoft's global application delivery network. It combines CDN caching, global HTTP load balancing, SSL offloading, WAF, and health-based routing (latency, priority, weighted). Built on Microsoft's global WAN (same backbone as Office 365). Supports anycast to route users to the nearest PoP, reducing round-trip time by 40–70%.
✅ Pros
Front Door: global presence in 120+ PoPs
Private DNS for VNet name resolution
Caching reduces backend load massively
Built-in DDoS and WAF on Front Door
❌ Cons
Front Door can be expensive for small sites
No UDP/TCP (HTTP only) on Front Door
DNS only (no registrar) — need to buy domain elsewhere

Relational
Azure SQL Database

Azure SQL Database is a fully managed PaaS database built on SQL Server. NoSQL Global
Azure Cosmos DB
🌍 The world's most distributed database. Single-digit millisecond latency anywhere on Earth. Supports 5 APIs: SQL, Mongo, Cassandra, Table, Gremlin.
Cosmos DB is Microsoft's flagship globally distributed, multi-model NoSQL database. Key differentiators: Global distribution — replicate data to any of 54+ Azure regions with a single click and get automatic failover. 5 consistency models — from Strong to Eventual, letting you trade consistency for latency. Guaranteed SLAs for latency (10ms P99 for reads), throughput, and availability. Supports multiple APIs so you can use existing Mongo, Cassandra, or Gremlin drivers. Serverless mode for dev/test (pay per RU), or provisioned throughput (RU/s) with autoscale for production. Use Change Feed for event-driven architectures.
✅ Pros
Multi-region writes (active-active)
5 consistency levels to choose from
Multi-API (Mongo, SQL, Cassandra)
Guaranteed <10ms P99 reads globally
❌ Cons
RU/s capacity planning is complex
Very expensive at high throughput
No joins or complex SQL queries
Partition key design is critical

CI/CD Platform
Azure DevOps
🔄 All-in-one DevOps platform: Git repos + CI/CD pipelines + work tracking boards + test plans + artifact storage. The complete DevOps lifecycle.
Azure DevOps includes 5 core services: Azure Repos (Git or TFVC source control), Azure Pipelines (YAML-based CI/CD, supports any cloud/language, 2,000 free minutes/month), Azure Boards (Agile work items, sprints, Kanban), Azure Test Plans (manual + automated test management), and Azure Artifacts (package feeds for npm, NuGet, Maven, Python). Integrates with GitHub, Jira, Slack, and Terraform natively.

Multi-stage with gates & approvals

Secrets + Automation
Key Vault & Azure Automation
🔑 Key Vault = your app's secret store (passwords, keys, certs). Azure Automation = scheduled scripts and runbooks that run without a server.
Azure Key Vault stores 3 types of objects: Secrets (DB passwords, API keys), Keys (RSA/EC for encryption/signing), and Certificates (X.509, auto-renewal). Access is controlled by RBAC or Access Policies. Applications use Managed Identity to authenticate to Key Vault without any credentials in code. Premium tier uses HSM (Hardware Security Module)-backed keys for FIPS 140-2 compliance.

Azure Automation provides Runbooks (PowerShell/Python scripts), Update Management (OS patching), DSC (Desired State Configuration), and Process Automation for scheduled or event-triggered tasks across Azure and on-premises (via Hybrid Runbook Worker).
✅ Pros (Key Vault)
No hardcoded secrets in code
Managed Identity = zero credential mgmt
HSM-backed keys for compliance
Audit log of every secret access
❌ Cons (Automation)
Runbook debugging is difficult
Complex for large-scale automation
Being superseded by Azure Automation + Bicep

Identity
Microsoft Entra ID (Azure AD)
👤 Microsoft's cloud identity platform. Manages who can log in, what they can access, and enforces MFA. The brain behind all Azure security.
Microsoft Entra ID (formerly Azure Active Directory) is Microsoft's Identity-as-a-Service platform used by 500M+ organizations. Core capabilities: SSO (single sign-on to 3000+ SaaS apps), MFA (enforced via Conditional Access), Conditional Access Policies (grant/block access based on user, device, location, risk), RBAC (built-in and custom roles), B2B Collaboration (invite external users), B2C (customer identity for public apps), Managed Identities (system/user-assigned identity for Azure resources), and Privileged Identity Management (PIM) for just-in-time admin access. Supports OAuth 2.0, OIDC, SAML 2.0, and WS-Federation.

Security Suite
Defender for Cloud + Azure Policy + Bastion
🛡️ Defender = cloud security posture scanner. Azure Policy = compliance enforcer. Bastion = secure VM access without exposing public IPs.
Microsoft Defender for Cloud (formerly Security Center + Defender) provides: Cloud Security Posture Management (CSPM) — continuous assessment with a Secure Score, recommendations ranked by risk. Cloud Workload Protection (CWP) — runtime threat detection for VMs (Defender for Servers), containers (Defender for Containers), SQL (Defender for SQL), storage, and more using Microsoft Threat Intelligence.

Azure Policy enforces governance at scale — define rules like "All VMs must have Defender enabled" or "Storage accounts must use HTTPS only" and Azure automatically audits or remediates non-compliant resources. Group policies into Policy Initiatives (e.g., CIS Benchmark, SOC 2, ISO 27001).

Azure Bastion provides browser-based RDP/SSH directly from the Azure Portal over HTTPS — no public IP on VMs, no VPN client needed, no jumpbox to manage.
✅ Pros
Secure Score: clear prioritized roadmap
Azure Policy auto-remediates drift
Bastion: zero exposed RDP/SSH ports
Defender: built-in MITRE ATT&CK mapping
❌ Cons
Defender for Cloud costs per resource
Policy remediation can have side effects
Bastion = one per VNet (can be expensive)
