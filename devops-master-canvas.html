Docker + Docker Desktop
Think of Docker as a magic lunchbox — it packs your app + everything it needs, runs anywhere
Core Concepts must
ImageA recipe/blueprint. Like a class in OOP. Read-only snapshot.
ContainerRunning instance of an image. Like a process from that blueprint.
DockerfileInstructions to BUILD an image. Like a recipe card.
RegistryStore for images. DockerHub = GitHub for images.
VolumePersistent storage. Data survives container restarts.
NetworkHow containers talk to each other. bridge/host/overlay.
Must-Know Commands
# Build & Run docker build -t myapp:1.0 . docker run -d -p 8080:80 myapp:1.0 docker run -it ubuntu bash # Inspect & Debug docker ps -a docker logs -f container_id docker exec -it container bash docker inspect container_id # Cleanup docker system prune -af docker volume prune
Docker Compose advanced
PurposeRun MULTI-container apps with one command. Like an orchestra conductor.
servicesEach container = one service. app, db, redis, nginx etc.
depends_onStart order. DB starts before app.
env_fileLoad env variables from .env file. Keep secrets out of code!
docker compose up -d docker compose down -v docker compose logs -f app docker compose scale app=3
Advanced Docker advanced
Multi-stage buildBuild in stage 1, copy only output to stage 2. Tiny final image!
Layer cachingUnchanged layers reused. Put rarely-changed stuff first in Dockerfile.
Health checkDocker knows if your app is actually alive, not just "running".
.dockerignoreLike .gitignore. Don't copy node_modules into image!
Docker Desktop (Local Dev)
Dev EnvironmentsFull dev setup in a container. Share with team via Git.
Kubernetes (built-in)Single-node K8s cluster in 1 click. Test K8s locally!
ExtensionsDisk usage, logs, Portainer, Snyk scan — all in GUI.
Resource limitsSet CPU/RAM in Settings. Don't let Docker eat your laptop!
Dockerfile Best Practices tips
Use slim/alpine basealpine = 5MB. ubuntu = 70MB. Huge difference in prod!
Run as non-rootUSER 1001. Security must. Don't run containers as root.
COPY vs ADDCOPY is explicit. ADD can untar/fetch URLs. Prefer COPY.
Combine RUN layersapt-get update && install in ONE RUN. Fewer layers = smaller image.

Kubernetes (K8s)
K8s is the manager who decides where your containers run, restarts them if they die, and scales on demand
The Big Picture
Control PlaneThe brain. API server, etcd (DB), scheduler, controller manager.
Node / WorkerThe muscle. Machines that actually run your pods.
PodSmallest unit. 1+ containers sharing network + storage. Like a tiny VM.
NamespaceVirtual cluster inside a cluster. Isolate teams/envs. dev/staging/prod.
kubeletAgent on each node. Reports to control plane. Runs pods.
Core Resources
DeploymentDesired state for pods. Handles rolling updates and rollbacks.
ServiceStable IP/DNS for pods. ClusterIP/NodePort/LoadBalancer.
ConfigMapNon-sensitive config as key-value. Inject as env or file.
SecretBase64 encoded sensitive data. Use Vault/Sealed Secrets in prod!
PersistentVolumeStorage that lives beyond pod death. DB data lives here.
IngressHTTP/S routing. One LB → many services. Host/path rules.
kubectl Cheatsheet
# Get info kubectl get pods -n mynamespace -o wide kubectl describe pod podname kubectl logs -f podname -c container # Apply/delete kubectl apply -f manifest.yaml kubectl delete -f manifest.yaml # Debug kubectl exec -it pod -- bash kubectl port-forward svc/app 8080:80 kubectl top pods kubectl rollout status deploy/app kubectl rollout undo deploy/app
Advanced K8s advanced
HPAHorizontalPodAutoscaler. Scale pods based on CPU/memory or custom metrics.
Resource Limitsrequests (guaranteed) vs limits (max). Always set both to avoid OOM kills.
Liveness ProbeIs app alive? K8s restarts if fails. Check /healthz endpoint.
Readiness ProbeIs app ready for traffic? No traffic sent until passes.
Taints & TolerationsReserve specific nodes for specific workloads. GPU nodes, etc.
RBACRole-Based Access Control. Who can do what to which resource.
StatefulSet vs Deployment
DeploymentStateless apps. Pods are interchangeable. Scale freely. web/api servers.
StatefulSetStateful apps. Pods have stable names. pod-0, pod-1. DBs, Kafka, Zookeeper.
DaemonSetOne pod per node. Log collectors, monitoring agents, network plugins.
Job/CronJobRun-to-completion tasks. Backups, reports, data migrations.
K8s Networking
CNI PluginNetwork plugin. Calico, Flannel, Cilium. Handles pod-to-pod comms.
DNSEvery service gets DNS: svc.namespace.svc.cluster.local
NetworkPolicyFirewall for pods. "Only frontend pod can talk to backend pod".
Service MeshIstio/Linkerd. mTLS, traffic management, observability between services.

ArgoCD — GitOps for K8s
Git is the truth. ArgoCD watches Git and makes K8s match it. Always. Forever.
GitOps Brain Model
GitOps = Git is source of truthK8s manifests live in Git. You push to Git, Argo deploys. No more manual kubectl apply in prod!
DeclarativeYou declare WHAT you want (desired state). ArgoCD handles HOW to get there.
Drift DetectionSomeone manually changed K8s? ArgoCD notices and alerts (or auto-reverts).
Core Concepts
ApplicationArgoCD resource. Points to Git repo + K8s cluster + namespace. The glue.
SyncMake K8s match Git. Manual or auto-sync. Like kubectl apply but smarter.
Synced/OutOfSyncHealth status. OutOfSync = someone touched K8s directly. Bad!
App of AppsOne Argo app that manages other Argo apps. Scale deployments!
RollbackOne click to go back to any Git commit. Time travel for deployments!
ArgoCD Commands
# Login & apps argocd login argocd.mycompany.com argocd app list argocd app get myapp argocd app sync myapp # Rollback to prev version argocd app history myapp argocd app rollback myapp 2 # Diff before sync argocd app diff myapp
ArgoCD + Helm/Kustomize
Helm charts in GitStore Helm charts in Git. Argo renders them and applies. Best practice!
Kustomize overlaysBase + overlays per env. base/dev/staging/prod. DRY K8s configs!
valueFilesDifferent values.yaml per environment in Argo app spec.
Interview Gold: ArgoCD pull-based model is more secure than push-based CI/CD. The cluster pulls from Git — no need to give CI pipeline cluster credentials!

Jenkins — CI/CD Workhorse
Jenkins = the factory line. Code in → test → build → deploy → done. Automated every step.
Jenkins Concepts
PipelineWhole CI/CD flow as code. Jenkinsfile in your repo. Version controlled!
AgentWhere pipeline runs. agent any = any node. agent {docker} = in container.
StageStep in pipeline: Build, Test, Scan, Push, Deploy. Visual in UI.
CredentialSecrets stored in Jenkins. Referenced as withCredentials. Never hardcode!
Shared LibraryReusable pipeline code across multiple projects. DRY principle.
Declarative Pipeline
pipeline { agent { docker { image 'node:18' } } environment { IMAGE = "myapp:${BUILD_NUMBER}" } stages { stage('Test') { steps { sh 'npm test' } } stage('Build') { steps { sh 'docker build -t $IMAGE .' } } stage('Deploy') { steps { sh 'kubectl apply -f k8s/' } } } post { failure { slackSend message: 'Build failed!' } } }
Advanced Jenkins advanced
Blue OceanModern UI for pipelines. Visual pipeline editor. Much nicer than classic UI.
MultibranchAuto-create pipelines for each Git branch. PR pipelines too!
Parallel stagesRun test suites in parallel. Cut pipeline time dramatically!
Stash/UnstashPass files between stages. Build artifacts between pipeline steps.
input stepPause pipeline for human approval before prod deploy. Manual gate.

Ansible — Config Management
Ansible = your robot sysadmin. Write once, configure 1000 servers at once. No agents needed!
Core Concepts
InventoryList of servers to manage. ini or YAML format. Groups: web, db, app.
PlaybookYour automation script in YAML. Series of tasks. The "recipe".
TaskOne action: install nginx, copy file, restart service.
RoleBundle of tasks for one purpose. nginx role, postgres role. Reusable!
ModuleBuilt-in tools. apt, yum, copy, template, service, docker_container, k8s etc.
IdempotentRunning twice = same result. Safe to re-run. Ansible ensures desired state.
Playbook Example + Commands
# playbook.yml - hosts: webservers become: yes tasks: - name: Install nginx apt: name: nginx state: present - name: Start nginx service: name: nginx state: started # Run commands ansible-playbook -i inventory.ini playbook.yml ansible-playbook playbook.yml --check # dry run ansible-playbook playbook.yml --diff # show changes ansible-playbook playbook.yml --tags deploy
Advanced Ansible advanced
VaultEncrypt secrets in playbooks. ansible-vault encrypt secrets.yml. Commit safely!
Jinja2 TemplatesDynamic config files with variables. nginx.conf.j2 → nginx.conf
HandlersTasks triggered by notify. Restart nginx ONLY if config changed.
Dynamic InventoryPull server list from AWS/GCP/Azure APIs automatically. No manual list!
Blocks & Error handlingblock/rescue/always. Like try/catch for tasks.

Terraform — Infrastructure as Code
Terraform = order cloud resources (EC2, VPC, RDS) from code. Like Amazon.com but for infrastructure.
Core Concepts
ProviderPlugin for AWS/GCP/Azure/K8s. Knows how to talk to that cloud API.
ResourceOne cloud thing: EC2 instance, S3 bucket, VPC, RDS. You declare it.
State fileTerraform's memory. Tracks what's created. STORE IN S3, not locally!
ModuleReusable resource group. vpc module, eks module. Like functions in IaC.
VariablesParameterize configs. Different values for dev/prod. terraform.tfvars
OutputExport values (IP, ARN) for other configs or pipelines to use.
Terraform Workflow
terraform init
→
terraform plan
→
terraform apply
→
terraform destroy
terraform init # download providers terraform plan -out=tfplan # preview changes terraform apply tfplan # create resources terraform state list # what's managed terraform import aws_instance.web i-1234 # import existing terraform workspace new staging # separate envs
Advanced Terraform advanced
Remote BackendState in S3 + DynamoDB for locking. TEAM MUST. Never git commit tfstate!
WorkspacesSame code, different state. dev/staging/prod from one codebase.
data sourcesRead existing cloud resources. Look up AMI, VPC ID, etc. Read-only.
for_each / countCreate N resources dynamically. 3 EC2 instances from one block!
TerragruntWrapper for Terraform. DRY configs. Manage multiple envs cleanly.

Observability Stack
Prometheus + Grafana + Jaeger + Kibana + Zabbix + Uptime Kuma = Total system visibility
3 Pillars of Observability
📊 Metrics (Prometheus)Numbers over time. CPU=80%, requests/sec=1000, error_rate=0.1%. What is happening.
📝 Logs (ELK/Kibana)Text records of events. Errors, warnings, debug lines. Why it happened.
🔗 Traces (Jaeger)Full journey of a request across microservices. Where it slowed down.
When to use which tool
Prometheus → Grafana"Show me CPU/memory trends for the last 7 days. Alert when >90%."
Kibana (ELK)"Find all ERROR logs from payment service between 2pm-3pm today."
Jaeger"Why is this API call slow? Show me which microservice is the bottleneck."
Zabbix"Monitor bare metal servers, network devices, legacy systems at scale."
🔥 Prometheus
Pull modelPrometheus SCRAPES metrics from /metrics endpoint. Apps expose it, Prom fetches it every 15s.
PromQLQuery language. rate(http_requests_total[5m]) = req/sec over 5 min average.
Exportersnode_exporter (OS), kube-state-metrics (K8s), blackbox_exporter (URLs). Bridges for things that don't have /metrics.
AlertManagerRoutes alerts to Slack/PagerDuty/email. Silences, inhibitions, grouping.
Recording RulesPre-compute expensive queries. Faster dashboards. Save as new metric.
# PromQL Examples rate(http_requests_total[5m]) # req/sec histogram_quantile(0.99, ...) # p99 latency sum by(pod) (container_memory_usage_bytes) up == 0 # down targets
📊 Grafana
Data SourcesConnect to Prometheus, Loki, Elasticsearch, InfluxDB, even SQL. One UI for all!
PanelsGraph, stat, gauge, table, heatmap, alerting panels. Drag-drop dashboard builder.
VariablesDashboard variables = dropdowns. Switch between pods/namespaces dynamically.
AlertingGrafana Unified Alerting. Alert from any data source. Route to Slack/PD.
ProvisioningDashboards + datasources as code (YAML). Version control your dashboards!
Grafana LokiLike Prometheus but for LOGS. Cheap. K8s-native. Pairs with Prometheus perfectly.
🔗 Jaeger (Distributed Tracing)
TraceFull path of one request. User → API gateway → auth service → DB. See each hop.
SpanOne unit of work within a trace. Auth service processing = one span.
TraceIDUnique ID that follows request across all services. Pass in headers!
SamplingDon't trace 100% of requests. 1% sampling reduces overhead. Head vs tail sampling.
OpenTelemetryThe standard now. OTel SDK → Jaeger/Zipkin/Tempo. Instrument once, send anywhere!
📝 ELK Stack + Kibana
E = ElasticsearchSearch engine + storage. Full-text search on logs. Stores billions of log lines.
L = LogstashLog pipeline. Collect → parse → transform → send to ES. Heavy but powerful.
K = KibanaUI on top of ES. Discover logs, build visualizations, dashboards.
BeatsLightweight shippers. Filebeat (files), Metricbeat (OS metrics), Packetbeat (network).
KQLKibana Query Language. status:error AND service:payment. Filter logs fast.
Index lifecycleHot → warm → cold → delete. Manage storage costs automatically.
🖥️ Zabbix
Best forLegacy infra, bare metal, network devices (SNMP), Windows servers. Enterprise scale.
Agent/AgentlessZabbix agent installed on servers. Or agentless via SNMP/SSH/WMI.
TemplatesReusable monitoring sets. Linux template = CPU+RAM+disk+network in one click.
TriggersConditions that fire alerts. CPU > 90% for 5 mins → ALERT. Severity levels.
ProxyZabbix proxy collects data from remote sites, forwards to server. Distributed monitoring.
ActionsWhat to do on trigger: send email, run script, create ticket, notify Slack.
💚 Uptime Kuma
What it isSelf-hosted uptime monitoring. Beautiful UI. Like Uptime Robot but you own it.
Monitor typesHTTP/HTTPS, TCP port, DNS, Ping, Docker container, Push (heartbeat).
Status pagesPublic/private status page. Show clients your service health. Branded!
Notifications90+ integrations: Slack, Teams, PagerDuty, Telegram, Discord, webhook.
CertificatesSSL cert expiry monitoring. Alert 30 days before cert expires!

Git — Version Control Mastery
Git is a time machine for code. Never lose work, collaborate safely, track every change.
Core Commands
# Everyday git git clone url git status git add . && git commit -m "feat: add login" git push origin feature/xyz git pull --rebase # Branching git checkout -b feature/new git merge feature/new git rebase main # Undo stuff git reset HEAD~1 --soft # undo commit, keep changes git reset HEAD~1 --hard # undo + delete changes git revert abc123 # safe undo with new commit git stash && git stash pop
Git Branching Strategies
Git Flowmain + develop + feature/release/hotfix branches. Good for versioned products.
Trunk-basedAll devs commit to main frequently. Short-lived feature branches. Best for CI/CD!
GitHub Flowmain + feature branches + PRs. Simple. Deploy from main. Great for SaaS.
Feature flagsMerge unfinished features hidden behind flags. Enable per user/env. Ship safe!
Advanced Git advanced
cherry-pickApply one specific commit to another branch. Hotfix a bug in prod without full merge.
bisectBinary search to find which commit introduced a bug. INCREDIBLE for debugging.
reflogGod mode. See ALL git operations ever. Recover "deleted" branches.
hooksScripts that run on git events. pre-commit: lint/test. pre-push: build check.
Signing commitsGPG sign commits. Verified badge on GitHub. Trust your team's code.

Squid Proxy
Squid = traffic cop for internet. Control, cache, and log all outbound web traffic from your network.
What Squid Does
Forward ProxyClients → Squid → Internet. Company laptop can't reach internet directly. Must go via Squid.
CachingSquid saves web content. 2nd request = serve from cache. Saves bandwidth. Faster!
Access Control (ACL)Whitelist/blacklist URLs, IPs, time of day. Block social media during work hours!
SSL BumpingInspect HTTPS traffic. Man-in-the-middle (with company cert). Deep packet inspection.
LoggingEvery URL accessed. Who. When. How much data. Audit trail for compliance.
Squid Config Basics
# /etc/squid/squid.conf http_port 3128 acl localnet src 192.168.0.0/16 # Allow internal, block rest http_access allow localnet http_access deny all # Block specific sites acl blocked_sites dstdomain .facebook.com http_access deny blocked_sites # Restart & check logs systemctl restart squid tail -f /var/log/squid/access.log
Squid + Docker/K8s
Egress control in K8sPods route outbound traffic through Squid. Control what external APIs they can hit.
Container builds via proxydocker build with --build-arg HTTP_PROXY=http://squid:3128. Pull images through proxy.
Transparent proxyNo client config needed. Network routes all port 80/443 traffic to Squid automatically.
Sidecar patternRun Squid as K8s sidecar container for per-pod outbound control.

Monitoring Mindset + Career Tips
Know the WHY behind each tool. This is what separates 1-year from 3-year engineers.
SRE Golden Signals must know
LatencyHow long requests take. p50/p99/p99.9. Prometheus histogram. Don't just track averages!
TrafficHow many requests/sec. Load on your system. Capacity planning.
ErrorsError rate %. 5xx responses. Alert at 1% error rate. Business impact immediate.
SaturationHow "full" is your system. CPU/Memory/Disk near limit. Predict before it breaks!
SLI / SLO / SLA
SLI (Indicator)The metric you measure. "99.2% of requests returned 200 in last 30 days".
SLO (Objective)Target you set internally. "We aim for 99.9% uptime". Internal goal.
SLA (Agreement)Contract with customer. "We GUARANTEE 99.5% or you get credit". Legal!
Error Budget100% - SLO = error budget. 99.9% SLO = 43 min downtime/month allowed. Spend wisely!
Incident Response Flow
1. Alert fires (Alertmanager/Zabbix)
↓
2. Check Grafana dashboard (metrics overview)
↓
3. Check Kibana logs (find error messages)
↓
4. Check Jaeger (trace slow request)
↓
5. Fix → kubectl rollout / ansible / terraform
↓
6. Write postmortem (blameless!)
🧠 Interview Must-Knows must
Docker vs VMDocker shares host kernel = lighter, faster. VMs = full OS. Docker starts in seconds.
K8s vs Docker ComposeCompose = single host. K8s = multi-node cluster, self-healing, production scale.
Push vs Pull CI/CDJenkins pushes to K8s (less secure). ArgoCD pulls from Git (more secure). GitOps = pull.
Blue-Green deployTwo identical envs. Switch traffic from blue to green. Instant rollback!
Canary deploySend 5% traffic to new version. Watch metrics. If fine, increase to 100%.
🎯 Your 1-Year Edge: You're not just "someone who runs docker commands." You own the FULL DevOps lifecycle: Code (Git) → Build (Jenkins/Docker) → Ship (ArgoCD/K8s) → Monitor (Prometheus/Grafana/ELK/Jaeger) → Alert (Zabbix/Uptime Kuma) → Infra (Terraform/Ansible). That's a complete loop. Most juniors only know 2-3 of these. You know ALL of them. Own it.
