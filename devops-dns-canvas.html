What is a Domain?

Think of a domain like a home address. Instead of memorising "go to house #93, street 184, city 216" — you just say "go to Alice's house". Domains do the same for computers.

🏠

Real Life Analogy

Your home has a physical address like 42 Elm Street, City. Computers have IP addresses like 93.184.216.34. A domain (example.com) is a friendly nickname for that IP so humans don't have to memorise numbers.

🧩

Anatomy of a Domain

api . example . com ↑ ↑ ↑ Sub Second Top Level domain Level Domain

TLD: .com, .org, .in, .io
SLD: your brand name
Subdomain: optional prefix

🏷️ Domain Registration — How GoDaddy Works

Buying a domain from GoDaddy is like paying a landlord to reserve your address in the global address book. Here's what happens behind the scenes:

1

You search for "myapp.com" on GoDaddy

GoDaddy checks if that name is available in the global registry.

2

You pay ~$12/year

GoDaddy becomes your "registrar" — the official holder of your domain rights.

3

GoDaddy registers it with ICANN

ICANN is the global authority that manages all domain names on Earth. They record your ownership.

4

You get a control panel

You can manage DNS records, nameservers, renewal, and email forwarding.

⚠️

Key Insight: GoDaddy is just the registrar — they hold the title deed. You can point the domain's DNS to any provider (like Cloudflare) while keeping it registered at GoDaddy.

The DNS System

DNS = Domain Name System. It's the internet's phonebook. When you type a domain, DNS secretly translates it to an IP address. Without DNS, you'd have to remember numbers for every website.

📖

Analogy: You want to call "Pizza Palace". You don't know their number, so you look them up in a phonebook. DNS is that phonebook — you give it a name, it gives you a number (IP address).

🔄 DNS Resolution — Step by Step

When you type example.com, here's what happens in under 100ms:

1
Browser Cache

Browser first checks if it already knows the IP from a previous visit.

2
ISP Resolver (Recursive DNS)

Your internet provider's DNS server looks up the answer on your behalf.

3
Root Name Server

The top of the DNS tree. There are 13 root server groups worldwide. They say "go ask the .com server".

4
TLD Server (.com server)

The .com server says "go ask the authoritative server for example.com".

5
Authoritative DNS Server

This is the final source of truth. It returns the actual IP address.

6
IP Returned → Browser Connects

Browser now has the IP and connects to your server. Done!

🔑 What are Nameservers?

Nameservers tell the world who is in charge of your DNS. Think of them as "this is which phonebook to use for my domain".

GoDaddy default nameservers: ns1.godaddy.com ns2.godaddy.com After switching to Cloudflare: liam.ns.cloudflare.com mary.ns.cloudflare.com ⚡ DNS control now belongs to Cloudflare!
💡

Why switch nameservers? Cloudflare's DNS is globally distributed and faster. Changing nameservers moves DNS management without moving your domain registration. It's like keeping your address but using a better phonebook company.

DNS Records Explained

DNS records are individual entries in your domain's "phonebook page". Each record type has a specific job. Here are all the important ones with real-world examples.

📍

A Record — The Main One

Maps your domain to an IPv4 address. This is the most common record.

example.com → 93.184.216.34 api.example.com → 54.20.10.5

Think of it as: "When someone asks for my domain, send them to this IP address."

📍📍

AAAA Record — IPv6 Version

Same as A record but for modern IPv6 addresses (longer format).

example.com → 2606:2800:220:1:248:1893:25c8:1946

IPv6 is the next-generation address system. Most servers still use IPv4 (A records).

🔀

CNAME Record — Alias

Points one domain to ANOTHER domain (not an IP). Used for subdomains.

www.example.com → example.com shop.example.com → myshop.shopify.com

Think of it as a nickname. "When they ask for www, send them to the main domain."

📧

MX Record — Email

Tells the world which server handles email for your domain.

example.com MX 10 mail.google.com example.com MX 20 mail2.google.com

The number (10, 20) is priority. Lower = preferred. Used for Gmail / Outlook etc.

📝

TXT Record — Text / Verification

Stores plain text. Used for domain verification, SPF, DKIM (email security).

example.com TXT "google-site-verification=abc123" example.com TXT "v=spf1 include:_spf.google.com ~all"

When Google/GitHub says "verify your domain" — you add a TXT record they give you.

🗂️

NS Record — Nameservers

Declares which nameservers are authoritative for your domain.

example.com NS liam.ns.cloudflare.com example.com NS mary.ns.cloudflare.com

These are set at your registrar (GoDaddy). They delegate DNS control to another provider.

TTL (Time To Live): Every DNS record has a TTL value in seconds. This is how long other servers cache your record before checking again. Low TTL = changes propagate faster. Before making DNS changes, lower your TTL to 60-300 seconds. After, you can raise it to 3600+.

Cloudflare — The DevOps Swiss Army Knife

Cloudflare sits between your users and your server, acting as a bouncer, a speed booster, and a security guard — all at once. And the free tier is genuinely incredible.

☁️

What Cloudflare is NOT: Cloudflare is mostly not a domain registrar. You still buy domains from GoDaddy (or similar). Cloudflare's job is to manage your DNS and stand in front of your server to protect and speed it up.

🚀

CDN (Content Delivery Network)

Cloudflare has servers in 300+ cities. Your images, JS, CSS get cached at the nearest city to your user. Instead of all traffic hitting your server in the US, a user in Chennai gets files from a nearby Cloudflare node.

SPEED
🛡️

DDoS Protection

DDoS = hackers flood your server with fake traffic to crash it. Cloudflare absorbs that attack. They handle up to 71 Tbps of attack traffic — your server never even sees it.

SECURITY

Free SSL

Cloudflare automatically gives your site a free SSL certificate. No configuration needed. Your visitors get the green 🔒 lock without you buying a cert from GoDaddy.

FREE
🧱

Cloudflare inspects incoming traffic and blocks known attack patterns (SQL injection, XSS, bot scraping). Like a bouncer who checks IDs and knows every troublemaker.

PRO PLAN
📊

Rate Limiting

Limit how many requests an IP can make per second. Stops brute-force attacks on your login page or API. "Only 10 requests per minute from this IP."

PRO PLAN

FREE + PRO

🌐 Cloudflare SSL Modes (Critical!)

When Cloudflare sits between users and your server, you need to configure how SSL is handled. This is one of the most important settings to get right.

MODEWHAT HAPPENSSAFE?
Flexible

User ↔ Cloudflare is encrypted. But Cloudflare ↔ Your Server is plain HTTP! Your server doesn't even need SSL. This is dangerous — your actual traffic is unencrypted.

❌
Full

User ↔ Cloudflare ↔ Server all encrypted. But Cloudflare doesn't verify your server's certificate. A self-signed or expired cert still works. Better, but not perfect.

⚠️
Full (Strict)

Best mode. User ↔ Cloudflare ↔ Server all encrypted. Cloudflare verifies your server has a valid certificate (Let's Encrypt works great here). Use this always.

✅

SSL, TLS & HTTPS

The green padlock in your browser. The "S" in HTTPS. Let's demystify exactly what happens when your browser says "this connection is secure".

🔒

SSL (Old — Deprecated)

Secure Sockets Layer. Invented in 1995 by Netscape. Had several security vulnerabilities. No longer used — only the name stuck around in everyday speech.

When people say "SSL certificate" they technically mean TLS.

🛡️

TLS (Modern Standard)

Transport Layer Security. The modern, secure replacement for SSL. TLS 1.3 (2018) is what all modern browsers use. Faster and more secure than ever.

Everyone still calls it SSL but every server runs TLS. It's just a naming legacy.

🌐

HTTPS = HTTP + TLS

HTTPS is just normal HTTP web traffic, but wrapped in a TLS encryption layer. Your browser negotiates a secret key with the server before sending any data.

HTTP sends data in plain text (anyone can read it). HTTPS encrypts everything.

🎯 What Does TLS Actually Give You?

🔐

Encryption

Your data is scrambled before sending. Even if someone intercepts the packets, they see gibberish. Like sending a letter in a locked box only the recipient can open.

✅

Authentication

TLS proves you're talking to the REAL server, not an impersonator. The certificate proves "this really is bank.com and not a fake". Prevents man-in-the-middle attacks.

🔏

Data Integrity

TLS ensures data wasn't tampered with in transit. The receiver verifies the data arrived exactly as sent. No one could modify your packet mid-journey.

Certificate Files
CSR, CA, CRT, PEM, KEY

When you set up HTTPS, you deal with several cryptic files. Here's what each file actually is — in plain English.

🔑

The Big Picture: You create a key pair (public + private). Send your public key to a Certificate Authority (CA). They issue a certificate proving your domain identity. You install cert + private key on your server.

🔑

.key — Private Key

Generated on YOUR server. This is your secret. Never share this with anyone, ever. It's the password that proves you own the certificate.

server.key ← SECRET! Never leave server

If someone gets your private key, they can impersonate your server. Treat it like a master password.

📋

.csr — Certificate Signing Request

A file you generate on your server and send to a CA. It contains your domain name, public key, and company info. The CA uses this to issue your certificate.

Server generates: server.csr Contains: domain, public key, org info You send this to: Let's Encrypt / DigiCert
📜

.crt — Certificate

The certificate issued by the CA. Contains your domain, your public key, the CA's signature, and an expiry date. This is what browsers validate.

server.crt ← Public — safe to share Contains: domain proof, expiry, CA signature
📦

.pem — Bundle File

A combined file containing your certificate + intermediate CA certificates in one. Many web servers (Nginx, Apache) want this format because it includes the full trust chain.

fullchain.pem = Your cert + Intermediate CA cert + (sometimes Root CA cert)

🏛️ Certificate Authority (CA) — The Trusted Third Party

A CA is an organisation that browsers trust to vouch for certificates. When your browser sees a certificate signed by Let's Encrypt, it trusts it because browsers come pre-loaded with a list of trusted CAs.

🆓

Let's Encrypt

Free, automated DV certificates. Renews every 90 days. Used by millions of sites. Perfect for DevOps with tools like Certbot.

💼

DigiCert

Paid, enterprise-grade. Used by banks, governments. OV and EV certificates. Very expensive but highly trusted.

🌐

GlobalSign

Another commercial CA. Popular for OV/EV. Used by large enterprises who need verified org identity in their certificate.

⛓️ Certificate Chain — Why It Matters

Your certificate doesn't work alone — it relies on a chain of trust going up to a Root CA that browsers have pre-installed.

Your Certificate (example.com) ↓ signed by Intermediate CA (Let's Encrypt R3) ↓ signed by Root CA (ISRG Root X1) ↓ trusted by Browser (pre-installed)
❌

Missing chain = SSL error! If you only install your cert without the intermediate, browsers show a scary "Your connection is not private" error. Always use the full chain file (fullchain.pem).

The TLS Handshake

Every time you open an HTTPS website, a "handshake" happens invisibly in milliseconds. It's like two strangers agreeing on a secret language before talking. Here's exactly what happens.

🤝 Step-by-Step Handshake

1

Client Hello

Your browser says: "Hi! I support these TLS versions and encryption methods. Here's a random number." It lists what algorithms it can use.

2

Server Hello + Certificate

Server picks a mutually supported encryption method and says: "Let's use TLS 1.3 + AES-256. Here's my certificate to prove who I am."

3

Browser Validates Certificate

Browser checks: Is the cert expired? Is it for the right domain? Is it signed by a trusted CA? If anything fails — big red warning page.

4

Key Exchange

Browser and server do math (Diffie-Hellman) to agree on a shared secret key — without ever sending the actual key over the internet. Magic!

5

Encrypted Session Begins

Both sides now have the same secret key. All future communication is encrypted with this key. The padlock appears. You're safe.

📊 Visualised

BROWSER SERVER | | |── ClientHello ─→| | | |←─ ServerHello ──| |←─ Certificate ──| | | |── Verify cert →| (browser checks CA) | | |── Key Exchange─→| |←─ Key Exchange──| | | |══ ENCRYPTED ════| |══ SESSION ════| | | GET /home HTTP/1.1 (encrypted) 200 OK + page data (encrypted)
⚡

TLS 1.3 speed: The newest version (1.3) does the handshake in 1 round-trip (vs 2 in TLS 1.2). And for repeat visitors, it can do 0-RTT — resuming instantly with no handshake at all.

🔮 Diffie-Hellman Key Exchange — The Magic Explained

How do two parties agree on a secret key without a spy seeing it? This is the genius of Diffie-Hellman, used in TLS:

🎨

Paint Analogy: Alice and Bob both start with yellow paint (public info). Alice adds her secret red, Bob adds his secret blue. They swap their mixed paints. Alice adds her red to Bob's blue-yellow — gets the same final colour as Bob who adds his blue to Alice's red-yellow. The spy only ever sees the mixed paints — never the secret colours. The final combined colour is the shared encryption key.

Here's the complete setup every professional DevOps team uses. GoDaddy for the domain, Cloudflare for DNS + security, Let's Encrypt on the origin server.

COMPLETE SETUP FLOW
1
Buy domain from GoDaddy (or Namecheap, Google Domains, etc.) — $12/year
2
Create Cloudflare account and add your domain → cloudflare.com/add-site
3
Get 2 nameservers from Cloudflare: e.g., liam.ns.cloudflare.com
4
Update nameservers in GoDaddy — GoDaddy panel → DNS → Nameservers → Custom → paste Cloudflare NSs
5
Wait 1–48 hours for DNS propagation (usually under 1 hour with Cloudflare)
6
Add DNS A record in Cloudflare: example.com → your server IP

On your server: Install Let's Encrypt cert with Certbot → certbot --nginx -d example.com
8
Cloudflare SSL: Full (Strict) — Cloudflare dashboard → SSL/TLS → Full (Strict) mode
9
Enable WAF + Rate Limiting in Cloudflare → Security → Done! 🎉

🏆 Best Practices — The Golden Rules

🌐

Rule 1: Buy domain anywhere, DNS on Cloudflare

It doesn't matter where you buy the domain (GoDaddy, Namecheap, Google). Always move your DNS to Cloudflare. The speed and security difference is enormous.

🔒

Rule 2: Always use Full (Strict) SSL

Never use Flexible mode. Install Let's Encrypt on your origin server (certbot), then set Cloudflare to Full (Strict). End-to-end encryption, zero cost.

🔄

Rule 3: Automate cert renewal

Let's Encrypt certs expire every 90 days. Use certbot's auto-renew cron job so you never get a cert expiry surprise at 3am. Set it and forget it.

0 12 * * * certbot renew --quiet
🛡️

Rule 4: Enable WAF + Rate Limiting

Even on the free plan, enable Cloudflare's managed rules. Add rate limiting on your login and API endpoints. Stops 99% of automated attacks cold.

🕵️

Rule 5: Use Cloudflare "Orange Cloud"

When adding DNS records in Cloudflare, make sure the orange cloud (proxy) is enabled. This hides your real server IP from attackers. Without it, they can bypass Cloudflare and DDoS your server directly.

📉

Rule 6: Lower TTL before changes

Before changing any DNS record, first reduce its TTL to 60-120 seconds. Wait for propagation. Make your change. Then restore TTL to 3600. This minimises downtime during migrations.
