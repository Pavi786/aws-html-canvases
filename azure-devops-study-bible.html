What is Azure?
☁️
Azure is Microsoft's Cloud
Microsoft Azure (founded 2010)
Core

Imagine you want to run a website. Normally you'd buy a server, plug it in, manage electricity, cooling, security — nightmare. Azure lets you rent all of that from Microsoft and only pay for what you use. No hardware. No data center. Just cloud.

🏨 Think of it as: Renting a hotel room instead of buying a house. You get the bed, AC, wifi — without worrying about the plumbing.
🗺️
Azure Global Infrastructure
Regions, Availability Zones, Data Centers
Global

Azure has 60+ regions worldwide — each region is a geographic location (like East US, West Europe). Inside each region are multiple Availability Zones — separate data centers with independent power & cooling so if one burns down, others keep running.

🏙️ Think of it as: A city (Region) with multiple hospitals (AZs). If one hospital goes dark, patients go to the next one. No downtime.
💳
Subscriptions & Resource Groups
Azure Hierarchy: Tenant → Sub → RG → Resource
Org

Everything in Azure is organized in a hierarchy. Tenant = your company's Azure account. Subscription = a billing container (like a department budget). Resource Group = a folder to group related resources. Resource = the actual thing (a VM, a database, etc).

🗂️ Think of it as: Company (Tenant) → Department (Sub) → Project Folder (RG) → Files (Resources).
🎯
Service Models: IaaS, PaaS, SaaS
The 3 ways to consume cloud
Concept

IaaS — You rent raw infrastructure (VMs, networks). You manage the OS and above. PaaS — You just write code, Azure handles the servers, OS, scaling. SaaS — You just use an app (like Office 365). Azure handles everything.

🖥️ Section 01 / 12
Azure Compute
Compute = the power to run your code. Azure gives you many ways to run apps — from raw VMs where you control everything, to serverless functions where you just upload code and Azure handles the rest.
🖥️
Virtual Machines (VMs)
Azure Virtual Machines
IaaS

A VM is a computer that lives in Azure's data center. You pick the size (how many CPUs, how much RAM), choose an OS (Windows/Linux), and it's yours. You manage the OS, patches, software — full control.

Sizes range from B1s (1 vCPU, 1 GB) to M-series (hundreds of CPUs)
You pay per second/hour even when idle — so turn them off when not needed!
Use for: legacy apps, custom OS setups, full admin control needs
🖥️ Think of it as: Renting a full computer from Microsoft. You control everything — but you're also responsible for keeping it updated and secure.
📈
VM Scale Sets (VMSS)
Azure Virtual Machine Scale Sets
IaaS

VMSS automatically creates and deletes VMs based on demand. Traffic spike? Azure spins up more VMs. Traffic drops? It shuts extras down. You define the min/max and scaling rules.

Auto-scaling saves money — don't pay for idle capacity
All VMs in a set are identical — same image, same config
Works great behind a Load Balancer
🏭 Think of it as: A factory that hires more workers when orders spike and sends them home when it's quiet — automatically.
🌐
Azure App Service
Azure App Service (Web Apps)
PaaS

Deploy web apps, REST APIs, or backends without worrying about servers. Just push your code (Node.js, Python, .NET, Java, PHP) and Azure handles the infrastructure, OS patches, scaling, and SSL certificates automatically.

Built-in CI/CD from GitHub, Azure DevOps, BitBucket
Deployment slots — deploy to "staging" then swap to "production" with zero downtime
Auto-scales based on CPU, memory, or request count
🏠 Think of it as: A fully furnished apartment — you bring your stuff (code), Azure handles the building, plumbing, and electricity.
💡 DevOps tip: Use deployment slots for blue-green deployments. Zero risk code releases!
⚡
Azure Functions
Azure Functions (Serverless)
Serverless

Serverless computing — you write a small piece of code (a "function") that runs ONLY when triggered. When idle, you pay nothing. When triggered (HTTP request, timer, queue message), Azure runs it instantly and you pay per execution.

Triggers: HTTP, Timer, Blob storage, Service Bus, Event Hub, CosmosDB
Max execution time: 5 minutes (consumption plan) or unlimited (premium)
Great for: image resizing, data processing, webhooks, scheduled jobs
⚡ Think of it as: A light switch — it only uses power when you flip it. No server running 24/7 just waiting.
⚠️ Cold Start: First execution after idle can be slow (1-3s). Use Premium plan to avoid this for latency-sensitive apps.
📦
Azure Container Instances (ACI)
Azure Container Instances
Container

Run a Docker container in Azure in seconds — no VM, no Kubernetes cluster needed. Just provide the container image and ACI runs it. Pay per second. Perfect for short-lived jobs, batch tasks, and dev/test environments.

Fastest way to run a container in Azure
Not for production at scale — use AKS for that
Can be part of a VNet for private networking
📦 Think of it as: Ordering food delivery — you get exactly what you asked for, no need to set up a kitchen (no server needed).
⚙️
Azure Kubernetes Service (AKS)
AKS — Managed Kubernetes
K8s

AKS is managed Kubernetes — it runs and manages your containerized apps at scale. Azure handles the Kubernetes control plane (free!), you just manage the worker nodes and your workloads. Covered in depth in the Containers section.

🚀 Think of it as: Azure is the captain and navigation system. You just tell it where to go (what containers to run), it handles everything else.
🌐 Section 02 / 12
Azure Networking
Networking connects all your Azure resources together and to the internet. Without it, nothing can talk to anything. Master this and you understand how data moves in the cloud.
🏗️
Virtual Network (VNet)
Azure Virtual Network
Foundation

A VNet is your own private network inside Azure. Resources inside a VNet can talk to each other securely. By default, nothing from the internet can reach inside unless you explicitly allow it. You define the IP address space (e.g., 10.0.0.0/16).

Split VNets into Subnets — like rooms in a house
VNet Peering — connect two VNets so they talk to each other
Resources in different VNets can't talk by default — you must peer them
🏠 Think of it as: Your private neighborhood. Houses inside can visit each other freely. Strangers from outside need an invitation (explicit rule).
🔀
Subnets
VNet Subnets
Segmentation

Subnets divide your VNet into smaller sections. Put web servers in a "public subnet", databases in a "private subnet". This way, your DB never directly touches the internet — only the web servers can reach it.

Public subnet — has route to internet gateway (internet-facing)
Private subnet — no direct internet access, only internal traffic
Best practice: separate subnets for web, app, and data tiers
🏘️ Think of it as: Floors in an office. Reception (public) = anyone can enter. Server room (private) = only employees with badge access.
🛡️
Network Security Groups (NSG)
NSG — Firewall Rules for Azure Resources
Security

NSGs are firewall rules that control traffic in/out of VMs or subnets. You create rules like "allow port 443 from internet" or "deny all traffic from IP x.x.x.x". Rules have a priority — lower number = checked first.

Inbound rules: control traffic coming into your resource
Outbound rules: control traffic going out
Default: Azure blocks all inbound, allows all outbound
🚪 Think of it as: A bouncer at a club with a list. "Port 80 and 443 — come on in. Everything else — stay out."
💡 Tip: Apply NSGs at the subnet level (not just VM) for defence in depth — multiple security layers.
⚖️
Azure Load Balancer
Azure Load Balancer (L4)
Traffic

Distributes incoming network traffic across multiple VMs so no single server gets overwhelmed. Operates at Layer 4 (TCP/UDP) — it doesn't understand HTTP, just raw network packets. Automatically removes unhealthy VMs from rotation.

Public LB — distributes internet traffic to your VMs
Internal LB — distributes traffic between services inside your VNet
Health probes — checks if VMs are alive before sending traffic
🚦 Think of it as: A traffic cop who sends cars to whichever toll booth has the shortest queue — evenly spreading the load.
🔀
Application Gateway
Azure Application Gateway (L7 LB)
Traffic

A smarter load balancer that understands HTTP/HTTPS. It can route based on URL — send "/api/*" to backend servers and "/images/*" to a storage account. Also includes a Web Application Firewall (WAF) to block SQL injection and XSS attacks.

URL-based routing: different backends for different URL paths
SSL termination: decrypt HTTPS at the gateway, send HTTP internally
WAF mode: blocks common web attacks automatically
📬 Think of it as: A smart mail sorter — "packages go to warehouse, letters go to office, parcels go to locker." The basic LB just delivers to the same door.
🌍
Azure Front Door
Azure Front Door (Global CDN + LB)
Global

Global load balancing + CDN + WAF in one. Routes users to the nearest Azure region for lowest latency. If one region goes down, it automatically routes to the next healthy one. Think of it as Application Gateway at a global scale.

Anycast routing: users connect to nearest Azure PoP globally
Global failover: auto-redirects if a region fails
Caching: serves static content from edge nodes (CDN)
✈️ Think of it as: An airline with hubs worldwide. You always board at the nearest airport — not fly to New York just to connect to London.
🔒
VPN Gateway
Azure VPN Gateway
Connectivity

Creates an encrypted tunnel between your on-premises network (your office) and Azure VNet over the public internet. So your office PCs can access Azure resources as if they were on the same local network.

Site-to-Site VPN: connect entire office network to Azure VNet
Point-to-Site VPN: individual developer VPN to Azure
Traffic goes over internet — not as fast as ExpressRoute
🔐 Think of it as: A secret underground tunnel between your office and Azure's building — secure, private, goes under the public street (internet).
🚄
ExpressRoute
Azure ExpressRoute
Connectivity

A dedicated private fiber connection from your office/datacenter directly into Azure's network — NOT over the public internet. Much faster, more reliable, lower latency. Great for enterprises with huge data transfers or strict compliance needs.

Bandwidth: 50 Mbps to 100 Gbps options
More expensive than VPN but much more reliable
Required for some financial/healthcare compliance standards
🚄 Think of it as: A private high-speed rail line between your office and Azure. VPN = driving on the public highway. ExpressRoute = your own private bullet train track.
💾 Section 03 / 12
Azure Storage
Azure offers multiple storage types for different use cases. Files, objects, disks, queues — each has its purpose. Understanding when to use which storage type is key to building efficient systems.
🗂️
Azure Blob Storage
Azure Blob Storage (Object Store)
Most Used

The most popular Azure storage. Store any unstructured data — images, videos, PDFs, backups, logs, app packages. Access via URL. Massively scalable and cheap. Three access tiers to save money based on how often you access data.

Hot tier — frequently accessed, higher storage cost, lower access cost
Cool tier — accessed less often, cheaper storage, higher access cost
Archive tier — rarely accessed (backups), cheapest storage, slowest retrieval (hours)
🗄️ Think of it as: A giant Google Drive for your applications. Throw any file in, get a URL, share anywhere. Never fills up.
💡 DevOps use: Store build artifacts, pipeline logs, Terraform state files, and app config files in Blob Storage.
📁
Azure Files
Azure Files (Managed File Share)
SMB/NFS

A fully managed file share in the cloud accessible via SMB or NFS protocol — the same protocol Windows file shares use. Mount it on VMs like a regular network drive (Z: drive). Share files between multiple VMs simultaneously.

Works with Windows and Linux VMs
Great for legacy apps that need file share access
Can replace on-premises file servers
📁 Think of it as: A shared network drive in an office (like \\server\shared), except it lives in Azure. Multiple PCs can access the same files simultaneously.
💿
Azure Managed Disks
Azure Managed Disks (VM Disks)
Block

These are the virtual hard drives attached to VMs. When you create a VM, it gets an OS disk automatically. You can attach additional data disks for more storage. Azure manages the underlying hardware — no disk failures to worry about.

Standard HDD — cheapest, for dev/test
Standard SSD — web servers, lightly loaded apps
Premium SSD — production databases, I/O intensive apps
Ultra Disk — highest performance, SAP HANA, SQL databases
💿 Think of it as: The hard drive inside your laptop — except Azure's "laptop" never physically fails because it's replicated 3x behind the scenes.
📋
Azure Queue Storage
Azure Queue Storage
Messaging

A simple message queue for decoupling components. One service puts a message in the queue, another service reads and processes it. Messages wait in the queue until consumed. Simple and cheap — not as feature-rich as Service Bus.

Messages stay in queue for up to 7 days
Stores millions of messages, very cheap
Use for: background jobs, order processing, task queues
📬 Think of it as: A suggestion box at a restaurant. Customers drop notes in, kitchen staff read and action them at their own pace. No one blocks anyone else.
🗃️
Azure Table Storage
Azure Table Storage (NoSQL)
NoSQL

A simple, cheap NoSQL key-value store. No SQL queries, no joins — just store rows of data with a Partition Key and Row Key. Great for storing large amounts of simple structured data cheaply. Part of Azure Storage accounts.

Much cheaper than CosmosDB for simple use cases
No complex querying — lookup by key only
Use for: logging, user sessions, simple entity storage
📓 Think of it as: A giant spreadsheet with billions of rows — fast to look up by row number, but can't do complex filtering or joins.
🪪 Section 04 / 12
Identity & Security
Security is not optional in the cloud. Azure's identity and security services control WHO can access WHAT, and protect your resources from threats. As a DevOps engineer, you must understand these deeply.
🪪
Azure Active Directory (Entra ID)
Microsoft Entra ID (formerly Azure AD)
Core IAM

Azure's identity service — manages users, groups, and applications. When you log in to Azure portal, you authenticate with Entra ID. It's also used for Single Sign-On (SSO), Multi-Factor Authentication (MFA), and managing access to applications.

Users & Groups: manage who's in your Azure tenant
App Registrations: let applications authenticate with Azure
Managed Identities: let Azure services authenticate to each other without passwords
🏢 Think of it as: Your company's HR department + security badge system. It knows who everyone is, what department they're in, and issues access badges.
💡 Managed Identity tip: Instead of storing credentials in code, give your VM or App a Managed Identity — Azure handles the auth automatically. No passwords!
🎭
RBAC — Role-Based Access Control
Azure RBAC
Permissions

Controls what actions users or services can perform on Azure resources. You assign a Role (set of permissions) to a Principal (user/group/app) at a Scope (subscription, resource group, or single resource). Principle of Least Privilege — give only what's needed.

Owner — full control, can manage access
Contributor — can create/delete resources, can't manage access
Reader — can only view resources, no changes
Custom roles possible: create exact permission sets you need
🎟️ Think of it as: A hotel keycard system. Some cards open all doors (Owner). Some open specific floors (Contributor). Some just let you look at the lobby (Reader).
🔐
Azure Key Vault
Azure Key Vault
Secrets

Securely stores and manages secrets (passwords, API keys), certificates (TLS/SSL certs), and cryptographic keys. Your applications fetch secrets from Key Vault at runtime — never hardcode sensitive values in code or config files again.

Secrets: store DB passwords, API keys, connection strings
Keys: encryption keys for data at rest (HSM-backed)
Certificates: manage TLS certs with auto-renewal
Full audit log: who accessed which secret, when
🏦 Think of it as: A bank vault with a camera. Your app shows its ID badge, gets what it needs, and everything is recorded. Secrets never leave in plain text.
🛡️
Microsoft Defender for Cloud
Defender for Cloud (formerly Security Center)
Threat Detection

Continuously monitors your Azure environment for security vulnerabilities and threats. Gives you a Secure Score — a percentage showing how well-protected you are. Alerts you when something suspicious happens like brute force attacks or unusual logins.

Secure Score: improve this to improve security posture
Recommendations: "Your VM should have disk encryption" — click to fix
Threat detection: alerts for SQL injection, crypto-mining, lateral movement
🕵️ Think of it as: A security guard who constantly walks through your building, finds unlocked doors, and alerts you when someone is behaving suspiciously.
📋
Azure Policy
Azure Policy
Governance

Enforces organizational rules across your Azure environment. Define rules like "All VMs must have tags", "Storage accounts must be encrypted", "Resources can only be created in US East region" — and Azure either blocks violations or flags them for review.

Deny mode: block non-compliant resources from being created
Audit mode: allow but flag for review
Remediation: auto-fix existing non-compliant resources
📜 Think of it as: The company rulebook enforced automatically. If someone tries to do something against the rules, Azure says "Nope, not allowed" before it even happens.
🔒
Multi-Factor Authentication (MFA)
Entra ID MFA + Conditional Access
Auth

MFA requires users to provide two forms of identity (password + phone/authenticator app). Conditional Access adds smart rules — like "only allow login from corporate devices" or "require MFA when logging in from outside the office network".

MFA blocks 99.9% of account compromise attacks
Conditional Access: "If user is in unknown location → require MFA"
Privileged Identity Management (PIM): just-in-time admin access
🚪 Think of it as: A bank vault that needs both your key AND your thumbprint. Even if someone steals your key, they still can't get in without your thumb.

CI/CD & Azure DevOps
Azure DevOps is a complete suite for planning, building, testing, and deploying software. This is the heart of the DevOps engineer's daily work in Azure — automate everything so humans only do what matters.
🏢
Azure DevOps — The Full Suite
dev.azure.com — 5 integrated services
Platform

Azure DevOps is not one tool — it's 5 services in one platform. You can use all 5 or mix with GitHub/Jira:

📋
Boards
Sprint planning, backlogs, Kanban boards
🌿
Repos
Git repositories, pull requests, code review
🔁
Pipelines
CI/CD, build, test, deploy automation
📦
Artifacts
Package management (NuGet, npm, Maven)
🧪
Test Plans
Manual & automated test management
🔁
Azure Pipelines (CI)
Continuous Integration Pipeline
CI

Every time a developer pushes code, the CI pipeline automatically kicks off — compiles the code, runs tests, builds a Docker image, pushes to container registry. Catches bugs early before they reach production. Defined in azure-pipelines.yml.

Code Push
→
Build
→
Unit Tests
→
Docker Build
→
Push to ACR
🏭 Think of it as: A quality check conveyor belt — every piece of code that rolls in gets tested automatically before being approved.
🚀
Azure Pipelines (CD)
Continuous Delivery / Deployment
CD

After CI passes, CD automatically deploys the app to environments: Dev → Staging → Production. You can add approval gates (a human must approve before production deploy), environment-specific variables, and rollback mechanisms.

Artifact
→
Deploy Dev
→
Approval Gate ✅
→
Deploy Prod
✈️ Think of it as: Autopilot. Once a plane (code) passes safety checks, it automatically flies to each destination (environment) in order — pilot only needed to approve landing.
🐙
GitHub Actions for Azure
GitHub Actions + Azure integration
CI/CD

GitHub Actions is GitHub's CI/CD tool that integrates deeply with Azure. Use Azure-specific actions like azure/login, azure/webapps-deploy, azure/aks-set-context. Modern teams often prefer GitHub Actions over Azure Pipelines for its simplicity and GitHub integration.

Defined in .github/workflows/*.yml files
Triggered by push, PR, schedule, or manual click
Azure publishes 300+ official GitHub Actions
⚙️ Think of it as: GitHub Actions is like Azure Pipelines' cousin that lives next door — does the same job, lives in GitHub, works great with Azure too.
📦
Azure Artifacts
Azure Artifacts (Package Feeds)
Packages

A private package registry — store and share your own internal NuGet, npm, Maven, or Python packages within your organization. Pipeline builds packages and pushes to Artifacts; other pipelines pull them as dependencies. No public npm account needed for internal code.

Upstream sources: proxy public registries (npmjs.com) AND serve your private packages
Retention policies: auto-delete old versions to save space
Role-based: control who can push/pull packages
📚 Think of it as: Your company's private library. Instead of borrowing from the public library (npm), you store your custom books here so only company people can access them.
📦 Section 06 / 12
Containers & Kubernetes
Containers let you package your app with all its dependencies so it runs identically everywhere. Kubernetes orchestrates many containers at scale. This is modern DevOps — if you know containers, you're employable anywhere.
🐳
Docker & Containers
Docker (The Container Foundation)
Foundation

A container packages your app + its runtime + libraries into one portable unit. "Works on my machine" becomes "works everywhere." Docker is the tool that builds and runs containers. A Dockerfile defines what goes in the container.

Image = blueprint (like a class in OOP)
Container = running instance of an image (like an object)
Containers are isolated from each other but share the OS kernel
Much lighter than VMs — starts in seconds vs minutes
📦 Think of it as: Shipping containers on cargo ships. A container from China arrives in New York and opens exactly the same — the contents don't care what ship or port they're on.
🗃️
Azure Container Registry (ACR)
ACR — Private Docker Registry
Registry

ACR is your private Docker Hub inside Azure. Store, manage, and pull container images securely. CI pipeline builds a Docker image and pushes to ACR. AKS or App Service pulls from ACR to deploy. Supports geo-replication across regions.

Geo-replication: replicate images to multiple regions for faster pulls
Image scanning: Defender scans images for vulnerabilities
Tasks: build images in ACR without local Docker
📸 Think of it as: Your company's private Instagram for Docker images. Only people with access can see/download your app's photos (images).
⚙️
Kubernetes Concepts
K8s: Pods, Nodes, Services, Deployments
K8s Core

Kubernetes (K8s) orchestrates containers at scale. Key concepts:

Pod — smallest unit, 1 or more containers that share storage & network
Node — a VM that runs pods (worker machine)
Deployment — describes desired state (run 3 replicas of my app)
Service — stable endpoint to access pods (pods can change, service doesn't)
Ingress — HTTP router for the cluster (like App Gateway for K8s)
Namespace — virtual cluster inside a cluster, for separation
🏙️ Think of it as: K8s is a city. Nodes = office buildings. Pods = offices inside buildings. Service = the building's reception desk address. Deployment = the city plan saying "we need 3 offices."
🚀
AKS — Azure Kubernetes Service
AKS — Managed K8s on Azure
Managed K8s

AKS is managed Kubernetes — Azure handles the control plane (the Kubernetes master/brain) for FREE. You only pay for the worker VMs (nodes) where your apps run. Azure handles upgrades, patching, and healing of the control plane.

Node Pools: groups of VMs (can mix sizes — GPU nodes for AI, regular for web)
Cluster Autoscaler: automatically adds/removes nodes based on load
Azure integrations: ACR pull, Key Vault secrets, Azure Monitor
Upgrade: one command to upgrade Kubernetes version across all nodes
🏗️ Think of it as: Azure is the foreman managing the construction crew (Kubernetes). You just say "I want 3 floors of office space" — Azure figures out the workforce, scaffolding, and safety.
💡 Helm: Use Helm charts to package K8s configs as reusable templates. Like apt/npm but for Kubernetes applications.
📊 Section 07 / 12
Monitoring & Observability
You can't fix what you can't see. Observability is the ability to understand what's happening inside your system. Azure gives you powerful tools to watch metrics, read logs, trace requests, and get alerted before users notice problems.
📡
Azure Monitor
Azure Monitor — The Central Hub
Core

The central monitoring service in Azure. Collects metrics (CPU, memory, disk) and logs from all Azure resources automatically. Everything else (Log Analytics, App Insights, Alerts) feeds into or off Azure Monitor.

Metrics: numerical data over time (CPU%, requests/sec, error rate)
Activity Log: who did what in Azure (created VM, deleted RG)
Resource logs: diagnostic data from individual services
Dashboards: pin any metric to a visual dashboard
🏥 Think of it as: The hospital's central nurse station — all patient (resource) vital signs feed into one screen. Nurses (DevOps) can see everything at a glance.
🔍
Log Analytics Workspace
Azure Log Analytics + KQL
Logs

A centralized store for all your logs — from VMs, apps, containers, networks, security. Query logs using KQL (Kusto Query Language). Find errors, trace requests, generate reports. Logs are retained for 30-90 days by default.

KQL — SQL-like language but optimized for log data
Send logs from ALL Azure services to one workspace
Build visualizations and workbooks from log queries
📚 Think of it as: A Google search engine for all your app's diary entries (logs). Ask "show me all errors from last night at 3am" — instant results.
💡 KQL example: AppExceptions | where TimeGenerated > ago(1h) | summarize count() by type
🔭
Application Insights
Azure Application Insights (APM)
APM

APM (Application Performance Monitoring) for your code. Add the App Insights SDK to your app (Node, Python, Java, .NET) and it automatically tracks: request rates, response times, exception counts, dependency calls, and user sessions. Find slow queries and errors in production.

Live Metrics: real-time stream of what's happening right now
Transaction search: find a specific user's request end-to-end
Application map: visual diagram of how your services call each other
Smart detection: ML finds anomalies automatically
🩺 Think of it as: A fitness tracker for your app. Heartbeat (requests/sec), sleep quality (response time), health alerts (error spikes) — all in one dashboard.
🚨
Azure Alerts
Azure Monitor Alerts + Action Groups
Alerting

Set up alerts that fire when metrics cross a threshold or logs match a pattern. When an alert fires, an Action Group handles the notification — call the on-call engineer (PagerDuty/phone), send an email, post to Slack/Teams, or trigger an Azure Function to auto-fix the problem.

Metric alert: "CPU > 90% for 5 minutes → alert"
Log alert: "More than 10 errors in last 15 min → alert"
Action Groups: teams of people/actions to notify. One group, many alerts
🚒 Think of it as: A smoke detector. Smoke detected (metric threshold hit) → alarm sounds → fire station called (action group). Auto-response.
📊
Azure Workbooks & Dashboards
Azure Monitor Workbooks + Dashboards
Visualization

Workbooks combine metrics, logs, and text into interactive reports. Dashboards are pinned metric/log charts visible on the Azure Portal home screen. Share operational dashboards with your team so everyone sees system health at a glance.

Workbooks: interactive reports combining multiple data sources
Dashboards: real-time visual of key KPIs, shared with team
Grafana integration: connect Azure Monitor to Grafana for richer visuals
📺 Think of it as: A cockpit dashboard in a plane — all vital dials in one view. Pilot (DevOps) sees everything without looking at 50 different screens.
📝 Section 08 / 12
IaC & Automation
Infrastructure as Code (IaC) means defining your cloud infrastructure in text files — version controlled, repeatable, reviewable. No more clicking through the portal. If code reviews are good for apps, they're good for infrastructure too.
🔧
ARM Templates
Azure Resource Manager Templates (JSON)
Native Azure

ARM Templates are Azure's native IaC language — large JSON files that describe every Azure resource you want to create. They're powerful but verbose and hard to read. Azure guarantees idempotency — run the same template twice, get the same result.

100% Azure native — no extra tools needed
Can be stored in git and deployed via pipeline
Downside: JSON is verbose and difficult for humans to write/read
📐 Think of it as: An architectural blueprint in JSON. Exact, complete, but requires an architect to read. One blueprint → identical buildings every time.
💪
Bicep
Azure Bicep — ARM's friendlier cousin
Native Azure

Bicep is Microsoft's answer to "ARM is too hard." It's a Domain Specific Language (DSL) that compiles to ARM JSON. Much cleaner syntax, IDE intellisense, modular. Write 30 lines of Bicep to replace 200 lines of ARM JSON. Azure-only tool.

Transpiles to ARM — same engine under the hood
Modules: reuse Bicep files like functions/libraries
Tight VS Code integration with autocomplete
Microsoft-recommended for pure Azure environments
✨ Think of it as: ARM Templates is assembly code. Bicep is Python. Same machine understands both — but Bicep is way nicer to write.
🌍
Terraform
HashiCorp Terraform (Multi-cloud IaC)
Multi-Cloud

Open-source IaC tool that works with Azure, AWS, GCP, and 1000+ providers. Uses HCL (HashiCorp Config Language). Plan → Apply → Destroy workflow. Terraform tracks state of your infra in a state file so it knows what changed.

terraform plan — shows what WILL change, no actual change yet
terraform apply — applies the changes to real infra
terraform destroy — tears down everything in state
State file: must be stored remotely (Azure Blob) for teams
🌍 Think of it as: A universal remote control that works with every TV brand (every cloud). Learn once, work everywhere.
💡 Career tip: Learn Terraform. It's the industry standard. Skills transfer between Azure, AWS, and GCP jobs.
🤖
Ansible & Azure Automation
Configuration Management
Config Mgmt

Terraform creates infra. Ansible configures it. Ansible uses YAML playbooks to install software, set configs, and manage VM state — agentless (uses SSH/WinRM). Azure Automation is Azure's native tool for runbooks and update management.

Ansible: install Nginx, configure firewall, deploy app — on any VM
Azure Automation Runbooks: PowerShell/Python scripts that run on a schedule
Update Management: auto-patch VMs across your fleet
🏗️ Think of it as: Terraform builds the house (infra). Ansible furnishes it — installs furniture (software), sets the thermostat (config), arranges everything perfectly.
🗄️ Section 09 / 12
Azure Databases
Azure offers managed databases for every use case — relational (SQL), NoSQL, cache, and analytics. "Managed" means Azure handles backups, patching, scaling, and HA. You just use the database.
🗃️
Azure SQL Database
Azure SQL Database (Managed SQL Server)
Relational

Fully managed SQL Server in the cloud. Write SQL queries, create tables, run stored procedures — exactly like SQL Server but Azure handles backups, patching, HA, and auto-scaling. 99.99% SLA. Built-in AI performance tuning.

DTU vs vCore purchasing models — vCore is more flexible
Serverless tier: auto-pauses when not used → save money
Geo-replication: replicate DB to another region for DR
🗃️ Think of it as: Hiring a fully managed DBA (database admin) who never sleeps — backups, tuning, and failover are all handled without you asking.
🌌
Azure Cosmos DB
Azure Cosmos DB (Global NoSQL)
NoSQL

Microsoft's flagship globally-distributed NoSQL database. Store data in multiple formats (JSON documents, key-value, graph, column-family). Distribute to any Azure region with a click. Single-digit millisecond reads/writes globally. Automatic indexing on all fields.

Multi-region writes: users in Asia write to Asia, reads from Asia = low latency
5 consistency levels: from strict (always correct) to eventual (fastest)
Serverless option: pay per request, not per hour
🌍 Think of it as: A magical filing cabinet that instantly duplicates itself to every country — users in Tokyo read from Tokyo, users in NYC read from NYC. Always fast.
⚠️ Cost warning: CosmosDB charges per Request Unit (RU). Misconfigured queries can be very expensive. Always plan your data model carefully.
🐘
Azure Database for PostgreSQL
Azure PostgreSQL Flexible Server
Relational

Fully managed PostgreSQL. If your app uses Postgres, this is the Azure version — Azure handles patches, backups, HA (with standby replica). Supports extensions like PostGIS, pgvector. Flexible Server is the recommended option — you control maintenance windows.

High availability: primary + standby in same or different zone
Stop/Start: stop the DB to save money in dev environments
Azure also offers managed MySQL and MariaDB
🐘 Think of it as: Your Postgres database but you never have to install it, patch it, or back it up. Azure is the DBA on call 24/7.
⚡
Azure Cache for Redis
Azure Cache for Redis
Cache

Managed Redis — an ultra-fast in-memory data store. Store frequently accessed data in Redis so your app gets sub-millisecond responses instead of hitting the database every time. Also used for user sessions, leaderboards, and pub/sub messaging.

100x faster than hitting a SQL database
TTL: data auto-expires after N seconds (set and forget)
Use for: session storage, caching DB results, real-time counters
📋 Think of it as: A sticky note on your monitor. Instead of opening a filing cabinet (DB) every time, you glance at the sticky note. Way faster — but small and temporary.
🏭
Azure Synapse Analytics
Azure Synapse (Data Warehouse + Analytics)
Analytics

Enterprise analytics platform — combines data warehousing, big data analytics, and data integration in one service. Analyze petabytes of data with SQL or Apache Spark. Connects to Power BI for dashboards. For DevOps, it's often used for application telemetry analysis at scale.

Serverless SQL pool: query data in Azure Data Lake without moving it
Dedicated SQL pool: full data warehouse for BI reporting
Spark pool: big data processing with Apache Spark
🔬 Think of it as: A science lab that can analyze mountains of data. Where regular SQL is a kitchen knife, Synapse is a industrial food processor — for when the data is massive.
📨 Section 10 / 12
Messaging & Integration
Modern apps are made of microservices that need to communicate. Messaging services decouple components — Service A doesn't need to wait for Service B to be ready. They leave a message and move on. This is how scalable systems are built.
🚌
Azure Service Bus
Azure Service Bus (Enterprise Messaging)
Queuing

Enterprise-grade message broker. Supports Queues (point-to-point) and Topics/Subscriptions (publish-subscribe). Messages are guaranteed to be delivered at least once. Perfect for order processing, financial transactions, decoupling microservices.

Queue: one sender, one consumer — message processed once
Topic: one sender, many subscribers — each gets a copy
Dead-letter queue: failed messages go here for inspection
Guaranteed delivery: message not lost even if consumer is down
📬 Think of it as: A reliable postal service. Drop a letter (message) in the box, it's guaranteed delivered — even if the recipient is sleeping. They'll find it when they wake up.
📡
Azure Event Hub
Azure Event Hub (Big Data Streaming)
Streaming

Built for ingesting millions of events per second — like IoT sensor data, application telemetry, or clickstream data. Not for individual messages — for massive data streams. Consumers read events at their own pace. Data retained for up to 7 days.

Partitions: parallel lanes for reading events
Consumer groups: different services read the same stream independently
Kafka compatible: drop-in replacement for Apache Kafka
🌊 Think of it as: A river — data constantly flows. Consumers are fishermen at different points in the river, each catching what they need at their own pace.
⚡
Azure Event Grid
Azure Event Grid (Reactive Events)
Events

Reactive event routing — reacts to things happening in Azure. "Blob uploaded? Call this webhook." "VM deleted? Send a Teams notification." Event Grid routes events from Azure services (publishers) to handlers (subscribers) in real-time, with a push model.

Publishers: Blob Storage, Resource Groups, IoT Hub, custom apps
Handlers: Azure Functions, Logic Apps, Webhooks, Event Hub
Serverless, auto-scales, pay per event
🔔 Think of it as: A push notification system. "Something happened" → immediately notify whoever cares about that thing. Like phone notifications but for cloud events.
🔗
Azure Logic Apps
Azure Logic Apps (Low-code Integration)
Integration

Visual workflow builder — connect services without code. "When email arrives with attachment → save to Blob Storage → send Teams notification → update CRM." 400+ connectors for Salesforce, SAP, Twitter, GitHub, SQL, etc. Like Zapier/IFTTT but for enterprise.

No-code/low-code — business analysts can build workflows
400+ built-in connectors to SaaS and Azure services
Good for B2B integrations (EDI, AS2, SFTP workflows)
🔗 Think of it as: LEGO for business workflows. Snap blocks together: "If this → do that → then that." No programming needed for simple automation.
🛡️ Section 11 / 12
High Availability & Disaster Recovery
HA means your system stays up even when individual components fail. DR means your system recovers fast when something catastrophic happens (data center fire, region outage). Design for failure — it WILL happen.
🏙️
Availability Zones (AZ)
Azure Availability Zones
HA

Physical data centers within a region with independent power, cooling, and networking. Spread your VMs/services across 3 AZs — if AZ 1 has a power failure, AZ 2 and 3 continue serving traffic. The Zone-redundant SLA is 99.99% uptime.

Zone-redundant: Azure automatically spreads across 3 AZs
Zone-pinned: you choose which AZ (for latency-sensitive scenarios)
Key services support AZ: VMs, SQL, Storage, AKS, App Gateway
🏥 Think of it as: A hospital city with 3 hospitals in different neighborhoods. If one gets flooded, ambulances auto-route to the others. Patients (users) don't notice.
🔄
Availability Sets
Azure Availability Sets (VM HA)
HA

Older HA mechanism for VMs within a single data center. Azure guarantees VMs in an Availability Set are on different physical racks (Update Domains and Fault Domains). Protects against planned maintenance and hardware failures within one AZ.

Fault Domains: different power+network rack (protects hardware failure)
Update Domains: different update timing (protects during Azure maintenance)
Note: prefer Availability Zones over Availability Sets for new deployments
🔌 Think of it as: Making sure your backup generators are on different circuits. If one fuse blows, the other generator still runs.
🆘
Azure Site Recovery (ASR)
Azure Site Recovery
DR

Disaster Recovery as a Service. Replicates your VMs and on-premises servers to another Azure region continuously. If primary region goes down, failover to secondary in minutes. RTO (Recovery Time Objective) can be under 15 minutes. Test failovers without impacting production.

Replication: VMs + their disks replicated to secondary region
RPO: Recovery Point Objective — how much data you can afford to lose (minutes)
Test failover: simulate disaster without impacting real users
🆘 Think of it as: A shadow city — an exact copy of your city being built in another location at all times. If the original city floods, everyone moves to the shadow city immediately.
🌍
Azure Traffic Manager
Azure Traffic Manager (DNS-based LB)
Global LB

DNS-based global traffic routing. Directs users to the best endpoint based on routing method: Performance (closest region), Priority (failover), Weighted (% split), Geographic (route US users to US). Works with any internet-facing endpoint — even non-Azure!

Failover routing: primary → secondary if primary health check fails
Performance routing: route to lowest latency region for each user
Weighted routing: 90% to v1, 10% to v2 (canary deploy)
🗺️ Think of it as: A GPS that always finds the fastest route. If the motorway (primary region) is closed, GPS automatically reroutes you to the next fastest road (secondary region).
💰 Section 12 / 12
Cost Management
The cloud is pay-as-you-go — which means if you're not careful, bills explode. Cost management is a core DevOps skill. Understanding how to estimate, track, control, and optimize cloud spend is what separates good engineers from great ones.
📊
Azure Cost Analysis
Azure Cost Management + Billing
Visibility

Visualize your Azure spending. Break down costs by resource, resource group, service type, tag, or time period. See what's costing the most and spot unexpected spikes. Compare current month vs last month. Export cost data to CSV or Power BI.

Daily cost breakdown by service or resource
Filter by tags: "show me all costs tagged Environment=Production"
Forecast: ML-powered spend prediction for end of month
🧾 Think of it as: Your monthly bank statement with smart categorization. "You spent $400 on VMs, $80 on storage, $200 on AKS last month."
🔔
Budgets & Alerts
Azure Budgets
Control

Set a monthly spending budget and get email alerts when you reach 50%, 75%, 90%, or 100% of it. You can even trigger Action Groups (send email, call webhook) so teams are notified immediately when costs spike unexpectedly.

Set budgets at subscription, resource group, or resource level
Alert thresholds: email at 80%, call on-call at 100%
Actual vs Forecasted budget — warns before you hit the limit
💳 Think of it as: A credit card with a self-imposed limit and an alarm. Spend $800 of your $1000 limit? You get a warning. Spend $1000? You (and your boss) get a text.
🏷️
Resource Tags
Azure Tags (Cost Allocation)
Allocation

Tags are key-value labels you apply to any Azure resource. Use them to track costs per team, project, or environment. "Project=CRM, Environment=Prod, Owner=TeamA" — then filter Cost Analysis by these tags to see exactly what each team is spending.

Common tags: Environment, Project, CostCenter, Owner, Application
Azure Policy can enforce mandatory tags — prevent untagged resources
Tags don't inherit — parent RG tags don't flow to child resources automatically
🏷️ Think of it as: Labeling your groceries before putting them in a shared fridge. At billing time, everyone pays for what they labeled — no arguments about "whose cheese is this?"
💡 Best practice: Define a tagging policy on Day 1. Going back to tag hundreds of untagged resources later is painful.
💎
Reservations & Savings Plans
Azure Reservations + Savings Plans
Savings

Commit to 1 or 3 years of usage upfront (or monthly) and get up to 72% discount vs pay-as-you-go. Reservations lock to a specific VM size/region. Savings Plans are more flexible — commit to a $/hour spend, applies to any eligible compute.

Reservation: 1yr or 3yr commitment for specific VM = up to 72% off
Savings Plan: commit $X/hr of compute = up to 65% off, any VM type
Spot VMs: up to 90% off — but can be evicted anytime (for batch jobs)
Dev/Test pricing: 40-55% off if subscription is flagged as Dev/Test
✈️ Think of it as: Booking a hotel room 1 year in advance vs booking last-minute. Commit early → massive discount. Pay-as-you-go → rack rate.
