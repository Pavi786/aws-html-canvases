🔥 Firewall — iptables / nftables / ufw
🔥iptables — The Classic Firewall
iptables is the traditional Linux packet filter. Works with chains (INPUT, OUTPUT, FORWARD) and rules processed top-to-bottom. Every packet is checked against rules until a match or default policy applies.
# View all rules with line numbers
iptables -L -n -v --line-numbers

# Block an IP permanently
iptables -A INPUT -s 192.168.1.100 -j DROP

# Allow SSH only from specific IP
iptables -A INPUT -s 10.0.0.0/8 -p tcp --dport 22 -j ACCEPT

# Rate limit to prevent brute force (max 3/min)
iptables -A INPUT -p tcp --dport 22 -m state --state NEW -m recent --set
iptables -A INPUT -p tcp --dport 22 -m state --state NEW -m recent --update --seconds 60 --hitcount 4 -j DROP

# Save rules (Ubuntu/Debian)
iptables-save > /etc/iptables/rules.v4

# Flush ALL rules (DANGER!)
iptables -F # ← Removes ALL firewall rules!
⚠️ Always set a default DROP policy AFTER adding your ACCEPT rules. Never set DROP first or you'll lock yourself out!
Works on all old/new kernels
Huge documentation
Precise packet control
Stateful inspection
Syntax complex & verbose
Rules not persistent by default
IPv4/IPv6 separate tools
Being replaced by nftables
Always backup rules before changes: iptables-save > backup.rules
Test rules before making default DROP policy
Never run iptables -F on a live server without a recovery plan
Never allow port 0 or wildcard opens on public interfaces
Production SafeDevOps Essential
👁 LAYMAN EXPLANATION — PLAIN ENGLISH
🏨 Think of iptables like a hotel doorman with a rulebook. Every network packet trying to enter or leave gets checked. If it matches an ACCEPT rule — it gets in. DROP rule — blocked silently. Rules checked top-to-bottom, first match wins.
📝 Real Example: iptables -A INPUT -s 192.168.1.100 -j DROP = 'Block that specific IP address from ever reaching my server'
💡 Chain = which door: INPUT=incoming traffic, OUTPUT=outgoing, FORWARD=pass-through traffic
🛡️UFW — Uncomplicated Firewall (Ubuntu Friendly)
UFW is a frontend for iptables that makes firewall management human-readable. Perfect for servers where you want simple allow/deny without complex rule syntax. Behind scenes it still uses iptables.
# Enable UFW
ufw enable

# Default deny everything incoming
ufw default deny incoming
ufw default allow outgoing

# Allow specific services
ufw allow ssh # port 22
ufw allow 80/tcp # HTTP
ufw allow 443/tcp # HTTPS
ufw allow from 10.0.0.0/8 to any port 5432 # Postgres from LAN

# Rate limit SSH (6 attempts in 30 sec = block)
ufw limit ssh/tcp

# Check status verbose
ufw status verbose
ufw status numbered # see rule numbers

# Delete rule by number
ufw delete 3
💡 Use `ufw app list` to see available pre-defined app profiles (Nginx, Apache, OpenSSH etc.)
Run ufw allow ssh BEFORE enabling ufw to avoid lockout
Use `ufw limit` on SSH instead of just allow
Don't use UFW and another firewall manager simultaneously
Best for UbuntuBeginner Friendly
👁 LAYMAN EXPLANATION — PLAIN ENGLISH
🔐 UFW is iptables but with human-readable English commands instead of cryptic syntax. ufw allow ssh is way easier than the iptables equivalent. Under the hood UFW writes iptables rules for you automatically.
📝 Real Example: ufw allow 443/tcp = 'Let HTTPS traffic through the firewall' — much simpler than memorizing iptables syntax
💡 CRITICAL: Run ufw allow ssh BEFORE ufw enable — otherwise you lock yourself out permanently!

🔑 File Permissions & ACLs
chmod — Change Permissions
Controls who can read, write, execute files. Uses numeric (octal) or symbolic notation. Core to Linux security model.
# Octal notation: r=4, w=2, x=1
chmod 755 script.sh # rwxr-xr-x
chmod 644 config.conf # rw-r--r--
chmod 600 id_rsa # rw------- (private key!)
chmod 000 secret.txt # No access

# Symbolic notation
chmod u+x script.sh # Add execute for user
chmod go-w file.txt # Remove write from group+other
chmod a+r readme.md # Add read for all

# Recursive
chmod -R 755 /var/www/html
find /var/www -type f -exec chmod 644 {} \;
find /var/www -type d -exec chmod 755 {} \;
⚠️ 777 = everyone can write! NEVER use on servers. Max 755 for dirs, 644 for files.
👁 LAYMAN EXPLANATION — PLAIN ENGLISH
🔑 chmod controls who can read, write, or run a file with a 3-dial combination lock (owner/group/others). Numbers 755, 644 are shorthand: r=4, w=2, x=1. So 755 = owner gets 7(rwx), group gets 5(r-x), others get 5(r-x).
📝 Real Example: chmod 644 config.txt = 'Owner reads+writes. Everyone else reads only. Nobody can execute.'
💡 Quick guide: 755=standard folder/app, 644=standard file, 600=private key, 777=DANGEROUS (anyone can write)
chown + ACLs — Advanced Ownership
chown changes file ownership. ACLs (setfacl) extend Unix permissions to allow per-user/per-group fine-grained access beyond the owner/group/other model.
# Change owner and group
chown www-data:www-data /var/www/html
chown -R deploy:deploy /opt/app

# ACL — Give user read without changing owner
setfacl -m u:alice:r /etc/config

# Give group write access via ACL
setfacl -m g:developers:rwx /opt/project

# Set default ACL (applies to new files)
setfacl -d -m g:developers:rwx /opt/project

# View ACLs
getfacl /opt/project

# Remove ACL
setfacl -x u:alice /etc/config
AdvancedMulti-Team
👁 LAYMAN EXPLANATION — PLAIN ENGLISH
📋 chown changes who 'owns' a file — like changing the name on a mailbox. ACLs let you give specific users access without changing ownership. Perfect for: 'give Alice read-only access to this config without making her the owner'.
📝 Real Example: setfacl -m u:alice:r /etc/config = 'Give Alice read access to this file' — owner unchanged, no group changes
💡 ACLs solve 'I need one specific user to access this file, but they're not in the group' scenario
OpenSSL — Encryption & Certificates
OpenSSL handles TLS/SSL, encrypting files, generating keys, signing certificates. Every server admin needs these commands.
# Generate self-signed cert

🏗️LVM — Logical Volume Manager
LVM adds a virtualization layer over physical disks. Allows dynamic resizing of volumes, snapshots, and spanning across multiple physical disks. ESSENTIAL for production servers.

# Physical Volume → Volume Group → Logical Volume

# Create PV from disk/partition

vgcreate data_vg /dev/sdb

xfs_growfs /data # xfs

# Create snapshot (for backup/testing)
lvcreate -s -n snap_backup -L 10G /dev/data_vg/data_lv

# Add new disk to existing VG
pvcreate /dev/sdc
vgextend data_vg /dev/sdc

Snapshots for backup
Span multiple disks
Thin provisioning
Complexity overhead
Recovery harder than raw disk
Snapshot performance impact
👁 LAYMAN EXPLANATION — PLAIN ENGLISH

Mounting makes filesystems accessible. /etc/fstab makes mounts persistent across reboots. A misconfigured fstab can prevent server from booting — handle with care.

mount /dev/sdb1 /mnt/data
mount -t ext4 /dev/sdb1 /mnt/data
mount -o ro /dev/sdb1 /mnt/data # Read-only

# Mount NFS share
mount -t nfs server.local:/exports /mnt/nfs

# /etc/fstab entry (format: device mountpoint fstype options dump pass)
UUID=abc123 /data ext4 defaults,noatime 0 2
# Always use UUID not /dev/sdX (device names change!)

# Get UUID
blkid /dev/sdb1

# Test fstab SAFELY (before reboot!)
mount -a # Mount all from fstab — test it!

# Unmount
umount /mnt/data
umount -l /mnt/data # Lazy unmount (when busy)
fuser -m /mnt/data # See who's using mount
Always use UUID in fstab, never /dev/sdX
Add "nofail" option for non-critical mounts to prevent boot failure
Never edit fstab without testing with mount -a first
👁 LAYMAN EXPLANATION — PLAIN ENGLISH
🔌 mount is like plugging in a USB drive — makes disk contents accessible. /etc/fstab = auto-mount list on startup. ALWAYS use UUID not /dev/sdX in fstab — device names shift when you add/remove drives, UUIDs never change.
📝 Real Example: mount /dev/sdb1 /mnt/data = 'Plug in this disk partition and make its files accessible at /mnt/data'
💡 After editing fstab, ALWAYS test with mount -a before rebooting — bad fstab entry prevents boot!
💽RAID — Redundant Array of Independent Disks
RAID provides redundancy and/or performance using multiple disks. Software RAID with mdadm is reliable and free. Understanding RAID levels prevents data loss scenarios.

# RAID 1: Mirror (redundancy, 50% usable)
# RAID 5: Stripe+Parity (min 3 disks, 1 can fail)

# RAID 10: Mirror+Stripe (best performance+redundancy)

⚡ Kill signals are different ways to ask a process to stop. SIGTERM(15) = polite 'please stop gracefully'. SIGKILL(9) = 'stop RIGHT NOW, no questions asked' (can't be blocked). SIGHUP(1) = 'reload your config file'.
📝 Real Example: kill -9 1234 = 'Force-kill process 1234 instantly — like pulling its power cord. LAST resort only!'
💡 Try kill PID first. Wait 10 seconds. Then kill -9 PID. Jumping to -9 can corrupt database files!

🔐sudo — Privilege Escalation Done Right
sudo allows controlled privilege escalation. The /etc/sudoers file (edited with visudo) defines exactly who can run what as whom — the gold standard for server access control.

# Allow without password (for automation)

# Allow specific commands only
developer ALL=(ALL) /usr/bin/journalctl, /usr/bin/tail

# Alias for cleaner rules

devteam ALL=(ALL) NOPASSWD: DOCKER

# Run as different user

sudo -i # Root shell (with root env)
sudo -s # Root shell (current env)
Always use visudo to edit sudoers — it validates before saving
Prefer specific commands over ALL in sudo rules
Never add NOPASSWD ALL — always restrict to specific commands
👁 LAYMAN EXPLANATION — PLAIN ENGLISH
🦺 sudo is like a master key in a locked cabinet that must be signed out each use. Regular users can run specific admin commands — every use is logged in /var/log/auth.log. Much safer than giving everyone root access.
📝 Real Example: deploy ALL=(ALL) NOPASSWD: /bin/systemctl restart nginx = 'Deploy user can restart nginx only — nothing else'
💡 NOPASSWD for specific commands is great for automation. NOPASSWD: ALL = basically unlogged root access!

♻️logrotate — Log Rotation
logrotate automatically rotates, compresses, and deletes old logs. Without it, /var/log fills up and crashes your server. Every production server must have this configured.
# /etc/logrotate.d/myapp
/var/log/myapp/*.log {
daily # Rotate daily
rotate 14 # Keep 14 days
compress # Gzip old logs
delaycompress # Don't compress latest
missingok # OK if log missing
notifempty # Don't rotate if empty
sharedscripts
postrotate
systemctl reload nginx # Re-open log file
endscript
}

# Test your config
logrotate --debug /etc/logrotate.d/myapp

# Force rotation
logrotate --force /etc/logrotate.d/myapp

# View rotation status
cat /var/lib/logrotate/status
Always include postrotate to signal app to reopen log files
Set up logrotate for every custom application log
Don't keep logs forever — storage fills up. 14-30 days is typical.
👁 LAYMAN EXPLANATION — PLAIN ENGLISH
♻️ logrotate is a robot that automatically archives and shreds old logs. Without it, /var/log fills up and crashes your server. logrotate compresses old logs, deletes ones older than 30 days, creates fresh files — all on a schedule.

📝Bash Scripting — Pro Patterns
Professional bash scripts with error handling, logging, argument parsing. The difference between a script that breaks silently and one that alerts you when something goes wrong.
#!/bin/bash
# Pro bash script template
set -euo pipefail # Exit on error, undefined vars, pipe failures
IFS=$'\n\t' # Safer word splitting

# Logging function
log() { echo "[$(date +'%Y-%m-%d %H:%M:%S')] $*" | tee -a "$LOGFILE"; }
error() { log "ERROR: $*" >&2; exit 1; }

# Check dependencies
command -v docker >/dev/null || error "docker not found"

# Argument parsing
ENVIRONMENT="${1:-production}"
[[ "$ENVIRONMENT" =~ ^(staging|production)$ ]] || error "Invalid env"

# Trap for cleanup on exit
cleanup() { log "Cleaning up..."; rm -f /tmp/deploy.lock; }
trap cleanup EXIT

# Lock file (prevent concurrent runs)
LOCKFILE=/tmp/deploy.lock
( flock -n 200 || error "Another deploy running!" ) 200>$LOCKFILE

# Health check function
health_check() {
local url="$1" retries=5
for i in $(seq 1 $retries); do
curl -sf "$url" && return 0
sleep 5
done
return 1
}
Always use set -euo pipefail at the top of every script
Use trap for cleanup to handle unexpected exits
Never write scripts without error handling — silent failures cause data loss
AutomationPro Pattern
👁 LAYMAN EXPLANATION — PLAIN ENGLISH
📝 Bash scripting is like writing a recipe card for a sequence of commands. Instead of typing 20 steps every deploy, write them once as a script. Pro patterns: set -euo pipefail=stop on any error, trap=cleanup on crash, flock=prevent parallel runs.
