🖥️ COMPUTE
Compute

EC2

🧑‍🏫 In Plain English
Renting computers in the cloud. Pick the size (CPU, RAM), OS (Linux/Windows), and how many you need. Pay by the hour. Can turn off when done. Like a rental car, but for servers.
Types: t3 (burstable), m5 (general), c5 (compute), r5 (memory), i3 (storage)
Pricing: On-Demand (hourly), Reserved (1-3yr discount), Spot (90% cheaper, interruptible)
AMI: Pre-configured OS images
Security: Security Groups (firewall), Key Pairs (SSH auth)
aws ec2 run-instances \ --image-id ami-0c55b159cbfafe1f0 \ --instance-type t3.micro \ --key-name my-key \ --security-group-ids sg-12345678
CPUNetworkDisk I/OStatus Checks
Compute

Lambda

🧑‍🏫 In Plain English
Serverless functions. Write code, upload it, AWS runs it when needed. No servers to manage. Pay only for seconds it runs. Perfect for APIs, scheduled jobs, event processing.
Memory: 128 MB – 10,240 MB (CPU scales with memory)
Timeout: Max 15 minutes execution
Concurrency: 1000 concurrent by default
Triggers: API Gateway, S3, EventBridge, SQS, SNS, DynamoDB Streams
def lambda_handler(event, context): body = json.loads(event['body']) result = {'status': 'success', 'data': body} return { 'statusCode': 200, 'body': json.dumps(result) }
First invocation ~1-2s (cold start), subsequent <100ms
Mitigation: Provisioned Concurrency, Snapstart (Java), smaller packages

ECS & Fargate

🧑‍🏫 In Plain English
Run Docker containers. ECS manages them. Fargate = serverless containers (AWS handles VMs). EC2 = you manage servers. Containers are like shipping containers for apps.
Task Definition: JSON blueprint (image, memory, ports, env vars)
Service: Keeps desired # of tasks running
Fargate: Serverless, pay for CPU+RAM, no instance management
EC2 Launch: You manage instances, more control
aws ecs create-service \ --cluster my-cluster \ --service-name my-service \ --task-definition my-app:1 \ --desired-count 3 \ --launch-type FARGATE
AspectECS on EC2Fargate
Instance MgmtYou manageAWS manages
CostCheaperHigher

Compute

EKS & Karpenter

🧑‍🏫 In Plain English
Kubernetes on AWS. Industry-standard orchestrator for containers. Karpenter auto-scales EC2 nodes smartly. Choose if you have complex needs or multi-cloud plans.
Control Plane: AWS manages (you don't see it)
Worker Nodes: EC2 instances (managed or unmanaged)
Pod: Smallest K8s unit (like a container)
Pricing: $0.10/hour cluster + EC2 costs
eksctl create cluster \ --name my-cluster \ --region us-east-1 \ --nodegroup-name nodes \ --node-type t3.medium \ --nodes 3
Karpenter: Auto-scales EC2 nodes based on pod requests
Benefits: Faster scale-ups, right-sized nodes, mixed spot/on-demand
Compute

Auto Scaling

🧑‍🏫 In Plain English
Automatically add/remove servers based on demand. Peak traffic? Spin up more EC2s. Traffic drops? Shut them down. Set rules: "if CPU > 70%, add 2 servers". Saves money, keeps app responsive.
Launch Template: Blueprint (AMI, type, storage, security groups)
ASG: Min/desired/max capacity, health checks
Cooldown Period: Wait before next scale action
aws autoscaling create-auto-scaling-group \ --auto-scaling-group-name web-asg \ --launch-template LaunchTemplateName=web \ --min-size 2 --max-size 10 \ --desired-capacity 3 \ --availability-zones us-east-1a us-east-1b
Target Tracking: "Keep CPU at 50%" (simplest)
Step Scaling: "If CPU > 80%, add 2; if > 90%, add 5"
Scheduled: "Mon 8AM scale to 10, Fri 6PM scale to 2"
🌐 NETWORK & CDN
Network

VPC

🧑‍🏫 In Plain English
Your private cloud. Define IP ranges, create subnets (sections), control traffic. Like having your own private building with separate floors. Public = internet access, Private = internal only.
CIDR Block: IP range (10.0.0.0/16 = 65,536 IPs)
Subnets: Public/Private subdivisions
Security Groups: Instance-level firewall (stateful)
NACLs: Subnet-level firewall (stateless)
Internet Gateway: Bridge to internet
NAT Gateway: Outbound internet for private subnets
Route Tables: Direct traffic (IGW, NAT, VPN)
Layer 1 (Public): ALB, NAT Gateway Layer 2 (App): EC2/ECS instances Layer 3 (Data): RDS, ElastiCache, DynamoDB
Network

CloudFront

🧑‍🏫 In Plain English
Global CDN. Copies your content to 500+ servers worldwide. User in Tokyo? Gets file from Tokyo server, not US. Lightning-fast. Also blocks DDoS attacks.
Origin: S3, ALB, API Gateway, custom domain
Edge Locations: 500+ worldwide servers
TTL: Cache duration (60s - 31536000s)
Invalidation: Force refresh cache
Lambda@Edge: Run functions at edge
WAF Integration: Block malicious requests
SSL/TLS: HTTPS everywhere
Static assets: TTL 86400s (1 day+) HTML files: TTL 3600s (1 hour) API responses: TTL 0 (no-cache)
Network

API Gateway

🧑‍🏫 In Plain English
Front door to your backend. Receives HTTP requests, routes to Lambda/ECS, returns responses. Handles auth, rate limiting, CORS automatically.
Methods: GET, POST, PUT, DELETE, PATCH
Integration: Lambda, HTTP, AWS service, Mock
Authorizers: Custom auth, JWT, Cognito, OAuth2
Models: JSON Schema validation
Stage Variables: Different configs per env (dev, prod)
Usage Plans: Rate limiting, API keys, throttling
Logging: CloudWatch integration
AspectREST APIHTTP API
Latency~100ms~60ms
CostHigher70% cheaper
FeaturesFullCore only
Network

Route 53

🧑‍🏫 In Plain English
DNS phone book. When user types "example.com", Route 53 says "send them to this IP". Does health checks: if server A dies, automatically sends traffic to server B.
Hosted Zone: Container for DNS records
TTL: How long to cache answer (lower = more queries)
Health Checks: Monitor endpoints, send alerts
Traffic Flow: Visual routing policy editor
A: IPv4 address
CNAME: Alias to another domain
Alias: AWS-specific (ALB, CloudFront, S3)
MX, TXT, NS: Mail, text records, nameservers
Simple: One record, one value (most common)
Weighted: 70% to A, 30% to B (gradual migrations)
Latency: Route to nearest region (best performance)
Failover: Primary + standby (auto-switch on failure)
Geolocation: Route based on user location

S3

🧑‍🏫 In Plain English
Infinite file storage. Upload anything (images, videos, backups). Access via URL or CLI. Cheap ($0.023/GB), durable (99.99%). Versioning, encryption, lifecycle management built-in. Most popular AWS service.
Bucket: Container, globally unique name
Object: File with key (path) and metadata
Regions: Lower latency when nearby
Versioning: Keep old versions, restore deleted files
Encryption: SSE-S3 (free), SSE-KMS, SSE-C

Managed relational databases. AWS runs PostgreSQL, MySQL, Oracle, SQL Server for you. RDS = standard. Aurora = AWS-optimized, 5x faster, cheaper. No server management, automated backups, multi-AZ failover.

Multi-AZ: Standby replica (automatic failover)
Read Replicas: Read-only copies (scale queries)
Backups: Automatic daily, point-in-time restore (35 days)
Encryption: At rest (KMS) and in transit (SSL/TLS)
Parameter Groups: Database config
Enhanced Monitoring: 60+ metrics per second

DynamoDB

🧑‍🏫 In Plain English
NoSQL database. Stores JSON, super fast, scales instantly. No SQL, no schemas. Great for mobile, IoT, real-time analytics. "Single table design" = everything in one table.
Partition Key: Primary key, distributes data
Sort Key: Optional, enables range queries
GSI/LSI: Secondary indexes
Throughput: Provisioned (fixed) or On-Demand (auto)
Streams: Capture changes (Lambda trigger)
dynamodb = boto3.resource('dynamodb') table = dynamodb.Table('users') table.put_item(Item={ 'user_id': 'user-123', 'email': 'john@example.com', 'created_at': 1696000000 })
PK SK Attributes USER#123 METADATA {name, email} USER#123 ORDER#456 {amount, status} ORDER#456 ITEM#001 {product_id, qty}

🧑‍🏫 In Plain English
Ultra-fast in-memory cache. Redis or Memcached. Holds frequently-accessed data in RAM. Microseconds response. Perfect for sessions, leaderboards, rate limiting, real-time data.
Redis: Persistent, data types, pub/sub, Lua scripts
Memcached: Pure cache, simpler, distributed
Cluster Mode: Sharding across nodes (scale horizontally)
Replication: Primary + replicas (auto failover)

Messaging

SQS

🧑‍🏫 In Plain English
Message queue. Producer puts work in, consumers pull and process. Decouples systems. If consumer crashes, messages wait. FIFO = ordered (exactly once), Standard = fast.
Queue: Messages wait here
Visibility Timeout: Prevent double processing
Retention Period: How long messages stay (14 days default)
Dead Letter Queue: Failed messages go here
Long Polling: Wait for message (save cost)
sqs.send_message(QueueUrl=queue_url, MessageBody=json.dumps({'order_id': '123'})) messages = sqs.receive_message(QueueUrl=queue_url, MaxNumberOfMessages=10, WaitTimeSeconds=20)
AspectStandardFIFO
OrderingBest effortGuaranteed
DuplicatesPossibleNever
ThroughputUnlimitedUp to 300/s
Messaging

SNS

🧑‍🏫 In Plain English
Publish-subscribe. Publish once, goes to many subscribers (email, SMS, SQS, Lambda, HTTP). Great for alerts, broadcasts, fan-out patterns.
Topic: Channel where messages published
Subscriber: Email, SMS, SQS, Lambda, HTTP, SNS
Message Filter: Deliver only if attributes match
FIFO Topics: Ordered, exactly-once delivery
DLQ: Failed deliveries
sns.create_topic(Name='OrderAlerts') sns.subscribe(TopicArn=topic_arn, Protocol='email', Endpoint='admin@example.com') sns.publish(TopicArn=topic_arn, Subject='Order', Message='New order received!')
One message → Multiple subscriptions SNS Topic → SQS Queue → Worker → Lambda → Process → Email → Admin
Messaging

EventBridge

🧑‍🏫 In Plain English
Event router. When something happens (EC2 starts, order placed, file uploaded), route it to targets (Lambda, SQS, SNS, etc.). Like a smart switchboard. Schedule tasks like cron.
Event Bus: Channel for events
Rules: Match events, route to targets
Targets: Lambda, SQS, SNS, HTTP, ECS, etc.
Scheduler: Cron expressions for scheduled tasks
Pattern Matching: Filter events by attributes
events.put_rule(Name='DeploymentRule', EventPattern=json.dumps({ 'source': ['aws.ec2'], 'detail-type': ['EC2 Instance State-change'], 'detail': {'state': ['running']} })) events.put_targets(Rule='DeploymentRule', Targets=[{'Arn': lambda_arn, 'Id': '1'}])
AWS Sources: EC2, RDS, S3, CodePipeline, etc.
Custom Sources: PutEvents from your app
Scheduled: cron(0 8 * * ? *) = 8 AM daily

Kinesis

🧑‍🏫 In Plain English
Real-time data streaming. Thousands of events per second (stock ticks, logs, IoT sensor data). Data flows through stream, consumers process it in real-time. Like a firehose of events.
Stream: Sequence of events
Shard: Unit of throughput (1 MB/s input, 4 MB/s output)
Records: Data + partition key
Retention: 24 hours default (up to 365 days)
Auto-scaling: Adjust shards based on throughput
kinesis.put_record(StreamName='MyStream', Data=json.dumps({'sensor': 'temp', 'value': 23.5}), PartitionKey='sensor-1') response = kinesis.get_records(ShardIterator=iterator) for record in response['Records']: print(record['Data'])
Real-time Analytics: Process events as they arrive
IoT Data Ingestion: Millions of sensors
Log Streaming: Aggregate logs from apps
Stock/Crypto Ticks: Real-time pricing

CI/CD

CodePipeline

🧑‍🏫 In Plain English
Automated deployment pipeline. Code → Build → Test → Deploy. Triggered by git push. Orchestrates CodeBuild and CodeDeploy. From development to production automatically.
Pipeline: Series of stages
Stage: Source, Build, Test, Deploy, Manual Approval
Action: Action within stage (CodeBuild, CodeDeploy, etc.)
Artifacts: Output from one stage to next
Approval: Manual gate before deployment
Source (GitHub) → Build (CodeBuild) → Test (CodeBuild) → Manual Approval → Deploy (CodeDeploy) → Live!
pipeline = codepipeline.create_pipeline( name='my-pipeline', roleArn=iam_role_arn, stages=[ { 'name': 'Source', 'actions': [{ 'name': 'SourceAction', 'actionTypeId': {'provider': 'GitHub'}, 'configuration': { 'Owner': 'myorg', 'Repo': 'myrepo', 'Branch': 'main' } }] } ] )
CI/CD

CodeBuild

🧑‍🏫 In Plain English
Build server. Compiles code, runs tests, creates Docker images. Triggered by CodePipeline or git push. Pay only for build time (seconds). Scale automatically.
Project: Build configuration
Environment: OS + runtime (Ubuntu, Windows, custom Docker)
Artifacts: Output (JAR, WAR, Docker image to ECR)
Cache: Speed up builds (Docker layers, npm cache)
Logs: CloudWatch Logs, S3
version: 0.2 phases: install: runtime-versions: python: 3.9 build: commands: - echo "Building..." - pip install -r requirements.txt - python -m pytest tests/ post_build: commands: - echo "Building Docker image..." - docker build -t myapp:latest . artifacts: files: - '**/*'
Ubuntu: Standard Linux
Windows: For .NET apps
Custom Docker: Bring your own image
Compute: small, medium, large (scale up for faster builds)
CI/CD

CodeDeploy

🧑‍🏫 In Plain English
Deployment automation. Takes your build artifacts, deploys to EC2/On-Premises/Lambda. Strategies: All-at-once, rolling, canary, blue-green. Rollback on failure.
Application: What to deploy
Deployment Group: Where to deploy (EC2 instances, tags, ASG)
Revision: Version of code (S3 location, git commit)
Lifecycle Hooks: BeforeBlockTraffic, AfterBlockTraffic, ValidateService
Auto-rollback: On deployment failure or alarms
version: 0.0 Resources: - TargetService: Type: AWS::EC2::Instance Properties: Name: MyApp Hooks: BeforeInstall: - location: scripts/stop.sh ApplicationStart: - location: scripts/start.sh ApplicationStop: - location: scripts/stop.sh
All-at-once: Deploy to all at once (fast, risky)
Rolling: 25% → 50% → 75% → 100% (gradual)
Canary: 5% first, then 95% (test with few first)
Blue-Green: Parallel environments, switch traffic instantly

CloudWatch

🧑‍🏫 In Plain English
Monitoring and logging. Collect metrics (CPU, memory, latency), logs (app output), and traces. Create dashboards, set alarms (email when CPU > 80%), trigger auto-scaling.
Metrics: Data points over time (CPU%, memory, latency)
Logs: Text output from apps, Lambda, EC2
Log Insights: SQL-like queries on logs
Dashboards: Visual representation of metrics
Alarms: Trigger actions when threshold crossed
fields @timestamp, @message, @duration | filter @duration > 1000 | stats avg(@duration) as avg_duration by bin(5m)
Types: Threshold, anomaly detection, composite
Actions: SNS notification, auto-scaling, EC2 stop/reboot
State: OK, ALARM, INSUFFICIENT_DATA

X-Ray

🧑‍🏫 In Plain English
Distributed tracing. Track request from user, through API, to database. See bottlenecks, errors, latency. "Where is my request slow?" X-Ray shows you.
Trace: End-to-end request journey
Segment: Work done by service (Lambda, EC2, RDS)
Subsegment: Sub-operation within segment
Service Graph: Visualization of dependencies
Sampling: Trace subset of requests (reduce cost)
from aws_xray_sdk.core import xray_recorder @xray_recorder.capture('process_order') def process_order(order_id): # Automatically traced result = db.query(order_id) return result
Find Latency: Which service is slow?
Error Analysis: Where do requests fail?
Dependencies: What services call what?

IAM

🧑‍🏫 In Plain English
Access control. Who can do what? Create users, groups, roles. Attach policies (permissions). Principle of least privilege = give minimal permissions needed. Everyone gets own credentials.
Users: Individual people
Groups: Collection of users (Developers, Admins)
Roles: Services assume (Lambda, EC2, ECS)
Policies: JSON defining permissions (Allow/Deny)
MFA: Multi-factor authentication (2FA)
{ "Version": "2012-10-17", "Statement": [ { "Effect": "Allow", "Action": "s3:GetObject", "Resource": "arn:aws:s3:::my-bucket/*" } ] }
Least Privilege: Give minimal permissions needed
MFA Everywhere: Use 2FA for all users
Rotate Keys: Change access keys regularly
Assume Roles: Use roles, not long-lived keys

WAF & Shield

🧑‍🏫 In Plain English
WAF = Web Application Firewall. Block bad HTTP requests (SQL injection, XSS, bots). Shield = DDoS protection. AWS automatically defends against large attacks.
Web ACL: Collection of rules
Rules: Match requests (IP, User-Agent, SQL patterns)
Scope: CloudFront, ALB, API Gateway
Managed Rules: Pre-built rules (OWASP, SQL Injection)
Block if: - IP in blacklist - Contains SQL keywords (';', 'DROP', 'SELECT') - User-Agent = 'bot' - Request rate > 2000/5min (rate limiting)
Shield Standard: Free, basic DDoS protection
Shield Advanced: $3000/month, 24/7 support, advanced protection
DDoS Protection: Automatic mitigation of attacks

Orchestration

Step Functions

🧑‍🏫 In Plain English
Workflow orchestration. Chain Lambda functions, EC2, etc. "Do this, then that, if error do this". Like a state machine. Retries, error handling built-in. Visual workflow editor.
State Machine: Workflow definition
States: Task, Wait, Choice (if/else), Pass, Parallel
Execution: Run of state machine
Retries: Automatic retry on failure
Catch: Error handling, fallback states
{ "StartAt": "ProcessOrder", "States": { "ProcessOrder": { "Type": "Task", "Resource": "arn:aws:lambda:...", "Next": "CheckPayment" }, "CheckPayment": { "Type": "Choice", "Choices": [ { "Variable": "$.status", "StringEquals": "paid", "Next": "SendConfirmation" } ] } } }
Standard: Up to 1 year execution (asynchronous)
Express: Up to 5 minutes (synchronous, high throughput)

2. Spot Instances: 90% off, but interruptible (good for non-critical)
3. Savings Plans: Flexible across instances, regions
4. Right-sizing: Use appropriate instance type (don't over-provision)
5. Auto-scaling: Turn off unused capacity
6. Data Transfer: Minimize inter-region data movement
7. Storage Lifecycle: Move old data to cheaper tiers
8. Reserved Capacity: Aurora, RDS, ElastiCache
AWS Cost Explorer: Analyze spending by service, region, tag
Budgets: Set spending limits, get alerts
Reserved Instance Planner: Calculate savings
Compute Optimizer: Find over-provisioned instances
1. Delete unused EBS volumes, snapshots ($0.05-0.10 per GB/month)
2. Delete unused Elastic IPs ($0.005/hour when not attached)
3. Turn off development EC2 at 6PM (save 70% if off nights/weekends)
4. Use S3 Intelligent-Tiering (auto-optimize storage class)
5. Enable CloudFront caching (reduce data transfer costs)
6. Use Auto Scaling (pay only for what you use)
7. Review NAT Gateway ($.45/hour + data transfer = expensive)
